# 它现在能做什么

> 2026-10-24 ｜ ldv-mcp 0.1.0（内核 v0.1.38）
> 下面的输出**逐字来自实跑**（`python smoke_test.py` 与三个场景脚本），不是示意。

## 一句话

把你的 md 语料装成一棵**分层划分树**，然后用「同时满足哪几个条件」在树上查、
一支支下钻，并且**记住你先看哪一支**。agent 可以做你和它之间的翻译官——
但翻译的每一步都留痕、可查、可接管。

---

## 三个场景（实跑输出）

### 场景 A｜不建任何东西，先拿内置 36 项问一句

```
$ vocabulary
  → 语料 内置语料（ldv/corpus）｜36 项｜24 个可用键
  → 前 6 个键：['aliases', 'cues', 'evidence_status', 'evidence_status=有争议',
               'evidence_status=未验证', 'filled_by']

$ query require=["type=概念"]
  → 8 项 / 2 支｜ordered_by=default
  → 支序：['D13', 'D14']
  → 出处摘要：{'模型(DeepSeek-V4.1-Flash)': 8}
```

三件事一次说完：**词汇表先给你看**（查询只能用这些键，不许猜）；
答案是**一支支的**（不是一页列表，是树上的位置）；每条答案**带出处**
（这 8 条全是模型填的——内置语料的 `filled_by` 就这么写的）。

### 场景 B｜私人语料：agent 提透镜 → 冻结 → 问 → 钻 → 看记录

```
$ propose_spec（agent 提议一个方向函数，带理由）
  → 候选 a64fb0520c86｜语料指纹 36:f2c8a76b5b719a73

$ freeze_spec
  → 冻结 a64fb0520c86（force=False）

$ query（用上冻结声明里的方向函数）
  → spec={'id': 'a64fb0520c86', 'generated_by': 'agent',
          'corpus_fingerprint': '36:f2c8a76b5b719a73'}

$ drill D13（agent 代钻，actor 默认 agent）
  → recorded=True｜已记录（下钻 = 有用）；这批还剩 1 支待看

$ usage_status
  → 正式记录 1 条｜缓冲 1 批｜覆盖方向 1 个
  → 演员分解：{'记录数': 1, 'agent 声名的下钻': 1, '其余（人 / 未声明）': 0, …}
```

关键在中间那两步：**agent 可以提议怎么切分（带理由原文），但提议不等于生效**——
`freeze_spec` 之后才进系统，而且**再冻必须显式 force**（「悄悄换了个透镜」
与「主动换了透镜」在读到的树上长得一样，所以必须分成两个动作）。

### 场景 C｜问一个语料里没有的维度

```
$ query require=["作者国籍=中国"]
  → isError=True｜out_of_structure=True
  → 这些键不在词汇表里 —— 可能是拼错了；若确实没有这个维度，
    那是「超出结构」，请人介入，本层不猜
  → 建议：{'作者国籍=中国': []}
```

**它不猜。** 没有「作者国籍」这个维度，就说没有，并且把「拼错了」和
「真的没这个维度」分开报（建议列表空 = 没有相近的键，那不是拼写问题）。

## 能力清单（现在就能用）

| # | 能力 | 靠什么 |
|---|---|---|
| 1 | **词汇表先行** —— 查询前先知道能问什么 | `vocabulary`；键校验在入口**之前** |
| 2 | **结构化查询** —— 「同时满足 A、排除 B」⇒ 树上的若干支 | `query`；支序**原样**返回 |
| 3 | **下钻即反馈** —— 钻哪支，哪支以后先摆出来 | `drill` → 使用记录 → 倾向（只改次序，**答案集合逐字不变**） |
| 4 | **方向函数三选一** —— 键集 / 可达 / 顺序，各有适用场景 | `presets/` 三份人话 |
| 5 | **agent 可提议透镜** —— 带理由原文，可审计 | `propose_spec` |
| 6 | **首次使用即冻结** —— 之后只读文件，复现性回到文件层 | `freeze_spec`；不 force 不覆盖 |
| 7 | **语料变则声明作废** —— 指纹不符就报过期 | `spec_status` 的 `stale` |
| 8 | **答案带出处** —— 语料 / 模型填 / 已验证三类分开数 | `query` 的 `provenance` |
| 9 | **agent 操作全留痕** —— 每次调用一行，只追加 | `store/log/mcp-calls.jsonl` |
| 10 | **演员可分解** —— 多少记录来自 agent 声明的下钻 | `usage_status` 的 `actor_split` |

七件工具：`vocabulary` · `propose_spec` · `freeze_spec` · `spec_status` ·
`query` · `drill` · `usage_status`。

## 它现在**不能**做什么（诚实清单）

| 不能 | 为什么 |
|---|---|
| **不排序、不推荐** | 支序原样中转；「最相关的是……」这种话它不说 —— 排序即推荐，是红线 |
| **不主动找你** | 没有「你可能需要看这个」。它只回答你问的 |
| **不懂语义** | 「A 意味着 B」不做。它做结构：包含、可达、路径、反事实（删了会怎样） |
| **不接不可信存档** | 内核的持久化格式仍是可信输入假设；别把陌生存档喂给它 |
| **私人语料要自己摆** | 它不爬网、不导数据。语料 = 一个目录的 md 文件 |
| **没做规模验证** | 内置 36 项与复制它的私人语料上全绿；3907 项级别的语料**没在本产品里跑过**（内核跑过） |

## 怎么自己验

```bash
python smoke_test.py        # S1–S13：真起一个 MCP 会话，跑完全部工具
```

十三条里最要紧的四条：未知键**必须被拒**、重复冻结**必须被拒**、
支序必须与内核**逐字相同**、`provenance` 之和必须等于 `n_answer`。
它们判的是「约束是机制」——不是「agent 今天听话」。

## 已知的边界（不是缺陷，是形状）

- **分辨率随规模退化**：log 最大叶 对 log|U| 的斜率 ≈ 1.54 —— 语料越大叶子越粗。
  这是结构性质；要切更细，得加维度（预设就是干这个的）。
- **倾向带演员口味**：agent 代钻算有用（定的），所以次序会带上 agent 的翻译偏好。
  兜底是 `actor_split` 可分解 + 日志可接管，不是「不算」。
- **reach 上互相可达的项会被劈开**（`id` 是 tie-break）—— 已知形状，选 reach 预设时
  它的说明里写着。
