# 长场景实测：从第一条笔记起，12 天，六类问题

> 2026-10-24 ｜ 探针 `probes/long_scenario.py` ｜ 逐字输出 `probes/out/long_scenario.out.txt`

## 这个实验想回答什么

不是「模型会不会编」（那要真模型才能测），是三个能测的：

1. **同一批事实，在有限窗口下还能命中多少** —— 「答案偏移」的真实形态
2. **插件要花多少上下文** —— 每次查询吐多少字
3. **长流程里会不会撞到缺口** —— 撞到了 agent 补得上吗

## 对照怎么做的（不是稻草人）

| | 条件 |
|---|---|
| **WITH** | 插件：笔记进 store，问题走 `ask`（按需取回，与笔记总量无关） |
| **WITHOUT** | **上下文窗口 = 最近 5 条笔记**（FIFO，超出就挤掉最老的） |

「不用插件」最真实的形态**不是「没有记忆」，是「记忆有上限，早期的会掉出去」**。
所以对照不是「空 vs 有」，是「**有限的窗口 vs 可查的库**」。

⚠️ 事实是**运行时用固定种子生成的**（`lr=3.17e-6`、`尖峰 2.73` 这类值）——
不在任何训练数据里 ⇒ WITHOUT 命中的唯一途径是「它还在窗口里」。

## 结果

### ① 从空语料开始：做不到，只能从第 1 条起

```
空目录 ⇒ CorpusError: 找不到语料
```

内核把空目录当「找不到语料」——**这是对的**：空目录和路径写错长得一样，
静默当成「0 项」才是坑。所以场景从第 1 条笔记开始。

### ② 第 2 天撞到真缺口，agent 当场补上

```
ask require=[project=alpha] ⇒ ok=False｜out_of_structure=True
⇒ 拒收 → derive project（3 项） → 再查 ok=True（2 项）
```

原因：**自定义字段只进「字段名」键，不进「字段=值」键**（内核只对 `type` /
`evidence_status` / `source.kind` 这类枚举字段生成值键）。
agent 读回字段（`with_body` 的 `fields`）→ `derive` 一个 `project` 维度 → 能查了。

### ③ 答案偏移（核心读数）

```
检查点        d01.lr      d02.base    d03.不可复现    窗口字数
第  3 天      有/有        有/有        有/有          149
第  6 天      有/无        有/有        有/有          173
第 12 天      有/无        有/无        无/无          146
```

（`有/无` = WITH 有 / WITHOUT 无）

- **WITH 全程 3/3**：库里的东西，第 12 天照样查得到
- **WITHOUT 逐条掉出窗口**：第 6 天掉第一条，第 12 天三条全掉
- ⚠️ 注意这不是「答案变错」——是**答不出来了**。偏移的表现是**沉默**，不是错误。
  沉默比错误更难发现，这正是「上下文替代记忆」最危险的地方。

### ④ 六类问题（最后一天，WITH 侧）

| 类 | 问题 | 结果 |
|---|---|---|
| 事实 | alpha 第一次的 lr 与尖峰 | 5 项 / 指回 5 id / **命中** |
| 事实 | 组 A 的 baseline | 5 项 / 5 id / **命中** |
| 结构 | beta 线几条 | 4 项 / 4 id |
| 结构 | alpha 的实验几条 | 3 项 / 3 id |
| 边界 | 有没有客户投诉稳定性 | 3 项 / 3 id（答的是「没有投诉，是导出慢」） |
| 元 | 覆盖哪些项目 | 13 项 / 13 id |
| 追述 | 第 3 天记的那条（B 方案） | 4 项 / 4 id / **命中** |

**指回率 7/7，漏检 0**（事实都在库里，且都取到了）。

### ⑤ 成本：两条反直觉的

```
单次 ask 的构成（project=alpha）：
  整包 2923 字｜正文块 1633 字（56%）｜元数据 1290 字（44%）
```

1. **元数据占 44%**（`nodes` / `provenance` / 查询回显）。想压上下文，先压这里。
2. **「先看支再取 2 条」反而贵 29%**（15,359 vs 11,882 字）——
   因为两步各付一遍元数据。**省上下文的正解不是少调几次，是把单次返回压瘦。**

## 证不了什么（写清楚，别被读成别的）

1. **WITHOUT 是「窗口模型」，不是「真模型」**。它模拟的是「记忆有上限」，
   **不模拟「模型会不会编造」** —— 后者要接真模型才能测，这一趟没测。
2. **token 用字数量**，不是真 tokenizer。中文大致 1 字 ≈ 1 token、ASCII ≈ 4 字/token，
   这里只报字数，不做换算。
3. **规模小**：13 条笔记、窗口 5 条，都是刻意压小的 —— 关键是**比例**
   （窗口能装下的笔记数 ≪ 笔记总数），不是绝对量。
4. **没有测「多人 / 多会话」**：这一趟是单会话单 ldv。
