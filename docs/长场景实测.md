# 长场景实测：空库起，14 天，六类问题

> 2026-10-24 ｜ 探针 `probes/long_scenario.py` ｜ 逐字输出 `probes/out/long_scenario.out.txt`

## 这个实验想回答什么

不是「模型会不会编」（那要真模型），是三个能测的：

1. **同一批数值事实，在「窗口 + 压缩」下还能命中多少** —— 答案偏移的真实形态
2. **插件要花多少上下文** —— 每次查询吐多少字
3. **长流程里撞到缺口，agent 补得上吗** —— 且**不打断用户**

## 对照怎么做的（第二版，第一版不公平）

| | 条件 |
|---|---|
| **WITH** | 插件：笔记进 store，问题走 `ask`（按需取回，与笔记总量无关） |
| **WITHOUT** | **窗口 12 条 + 压缩**：写满就把最老的 3 条压成一句摘要 |

⚠️ **第一版把 WITHOUT 做成「FIFO 硬掉出」，那是不公平的** —— 真 agent 会压缩。
压缩的真实后果不是「什么都忘了」，是「**主题还在，数值没了**」。

事实由固定种子运行时生成（`lr=3.17e-6`、`尖峰 2.73`），不在任何训练数据里。

## 结果

### ① 空库能起来了（基石自动放）

```
空库 orient ⇒ 1 项（基石自动放的）｜键 5 个
```

内核把空目录当「找不到语料」（空目录与路径写错长得一样），所以插件在**空库时自动放一条基石**：
它不参与任何查询，真开始记东西后可以留着也可以删。

### ② 缺口不打断用户，agent 自己补

```
ask require=[project=alpha] ⇒ ok=False｜can_agent_fill=True
next_step=['derive 一个维度（把这类取值建成可查的轴，带理由与来源）',
           '或映射到 vocabulary 里已有的键（换个问法）']
⇒ 无此键 → can_agent_fill → derive project（2 项）→ 再查 ok=True（2 项）
```

原因：**自定义字段只进「字段名」键，不进「字段=值」键**（内核只给 `type` /
`evidence_status` / `source.kind` 这类枚举字段生成值键）。
用户看不到「拒收」这种消息 —— 它只出现在 agent 那一侧，附带「你能怎么补」。

### ③ 答案偏移（核心读数，阶跃而不是渐变）

```
检查点        d01.lr      d02.base    d03.不可复现    窗口字数
第  3 天      有/有        有/有        有/有          115
第  6 天      有/有        有/有        有/有          216
第  9 天      有/有        有/有        有/有          299
第 12 天      有/有        有/有        有/有          380
第 14 天      有/无        有/无        无/无          367   ← 第 13 天压缩
```

（`有/无` = WITH 有 / WITHOUT 无）

- **WITH 全程 5/5 保持**
- **WITHOUT 到第 13 天压缩时，三条数值一起没** —— 是**阶跃**，不是渐变
- ⚠️ 偏移的表现是**沉默**（答不出来），不是错误。沉默比错误更难发现。

### ④ 主题题：WITHOUT 不输（这才是公平的分界）

```
WITH    ⇒ 14 条都有 project 字段，查得到
WITHOUT ⇒ 压缩摘要里项目名还在：True
          （摘要：【摘要】早前 3 条笔记（项目：alpha/beta/gamma），…）
```

⇒ **压缩丢的是精度，不是话题。** 所以「插件 vs 压缩」的真实差别是：

| 问题类型 | 压缩后的上下文 | 插件 |
|---|---|---|
| 数值（lr 多少、baseline 多少） | **输** | 有 |
| 主题（覆盖哪些项目） | 不输 | 有 |
| 结构（beta 几条） | 输（要数全量） | 有 |
| 追述（第 3 天那条） | 输（细节没了） | 有 |

### ⑤ 全量重建是设计，不是补丁

```
全量重建派生维度：第 2 天 3 项 → 现在 14 项
覆盖率 {'covered': 14, 'uncovered': 1, 'note': '**还有 1 项没有这个维度的值**…'}
```

派生维度是**快照**（建完之后新写入的节点不在里面），所以**全量重建是常规动作**，
`coverage` 只负责告诉你「该重建了」。`uncovered: 1` 是那条基石 —— 它本来就没有 project。

## 证不了什么

1. **WITHOUT 是「窗口 + 压缩」模型，不是真模型**。它模拟「记忆有上限、摘要丢精度」，
   **不模拟「模型会不会编造」** —— 后者要接真模型才能测。
2. **字数量不是 token 数**。中文大致 1 字 ≈ 1 token、ASCII ≈ 4 字/token，这里只报字数。
3. **规模小**：14 条笔记、窗口 12 条，都是刻意压小的 —— 关键是**比例**
   （窗口容量 < 笔记总量），不是绝对量。
4. **压缩策略是机械的**（「早前 N 条，数值已略」）—— 真模型的摘要会保留什么，
   取决于它，不由我定。这一趟测的是「压缩必然丢精度」这个结构性后果。
