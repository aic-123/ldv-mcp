# 能力对账：内核能做的 vs 插件暴露的

> 2026-10-24 ｜ 原则（用户定）：**打包成插件只舍弃自由度，不牺牲能力。**

这张表是那条原则的账本。每一行写清：内核有、插件有没有、没有的话**是舍弃能力还是舍弃自由度**。

## 已暴露（八件工具）

| 内核能力 | 插件工具 | 说明 |
|---|---|---|
| 装载语料、算键集 | `orient` | 只读；`_data/<名字>/nodes` 是唯一真相源 |
| 在树上查一支（分区不重不漏） | `ask` | 键先过词汇表；支序原样 |
| 下钻 = 有用（两段通道） | `drill` | 记录只改次序，答案集合逐字不变 |
| 写入节点（`insert`） | `remember` | **只追加不覆写**（覆写就是改写记忆） |
| **派生维度**（`derived/*.json`，v0.1.36 的 `influence` 就是它） | `derive` | 不写回材料；删 sidecar 即逐字回退 |
| **反事实**（`core/impact.py`：`removal_impact` / `compare_prediction`） | `undo` | 答案集的变化**算出来**（`App.answer_set` 只由键决定 ⇒ 删一项只能丢掉它）；结构侧在**深拷贝**上真删（内核自己要求「给一份深拷贝」）⇒ 不需要恢复，**「恢复失败」这个红状态直接消失** |
| **反思**（`reflect.graded`，动机三档） | `next` | 按后果分档，不是分数 |
| **节点的标题与正文** | `ask`（默认） | 正文是主产物 ⇒ 默认给；`structure=true` 才连分支与谓词一起给 |
| **条目的身份（id）** | 本地 `handles.json` | agent 只看到**句柄**（第 n 条）；动作说 `n`，服务端查本地表换成 id —— 记录留在 ldv，agent 不背它 |

## 未暴露 —— 是「舍弃自由度」，不是「牺牲能力」

| 内核能力 | 为什么不做成工具 |
|---|---|
| 落盘 / 内核快照（`persist` / `snapshot`） | 内核快照是**可重建的缓存**。暴露它 = 多一个会漂的真相源（存档与语料不同步时，谁对？）。产品的真相源只有两个：语料、`derived/` |
| 建树计划 / 续建（`--plan` / `--snapshot` / `--plan-all`） | 同上：那是「把一棵树分几次建完」的调度，不是新能力。插件按需建，agent 不需要知道分几步 |
| 视图层（`view_spec` + `recognize`） | 产品层的对应物是**透镜**（`ask` 的 `lens`）。两套并存会让人分不清「哪个在定义方向」 |
| `ldv-msg/1` 协议（ldv ↔ ldv） | 那是两个内核之间的对讲。插件是「内核 ↔ agent」，不是同一件事 |
| 服务壳（`serve.py` 多租户 / 队列） | 另一个产品面。MCP 宿主自己就是那个壳 |
| 并发锁壳（`--locked`） | 内核那把锁护的是**一个进程内的内核对象**；产品这一层不需要它 —— 每次调用都新建一个 `App`，进程内本来串行。**跨进程**（两个会话指向同一 store）由产品自己的写锁护，见下 |

## 跨进程写：已经补上了（2026-10-24）

原来这条是账本里唯一标红的：两个宿主会话指向同一个 store 时，
`remember` / `derive` / `freeze` 的「先查再写」会互相踩 —— 两边都看到「没有」，
两边都写，后写的赢且**没有任何信号**。现在：

| 机制 | 在哪 |
|---|---|
| **写锁**（`O_CREAT\|O_EXCL` 抢 `.lock`，拿不到 ⇒ `StoreBusy`） | `checks/lock.py`；`remember` / `derive` / 自动冻结三处持锁 |
| **原子创建**（`create_exclusive`，已存在 ⇒ False，不 TOCTOU） | `remember`（同 id 双写只有一个成功） |
| **不许静默覆盖**（同名派生维度第二次必须拒，要换显式 `force`） | `derive` |
| **陈旧锁接管**（mtime 超 120 秒视为进程已死，抢过来并记 `_stale.txt`） | `checks/lock.py` |

⚠️ **边界说清楚**：
- 锁护**写**不护**读** —— 写是原子的（`os.replace`），读到的要么是旧的要么是新的
- 这是**本机写锁**，不是分布式锁：NFS / 网络盘上 `O_EXCL` 的语义不保证
- 被杀进程会留下 `.lock`，要等 120 秒接管 —— **这是设计，不是 bug**
  （判据 S18b 专门验这个遗留）
- 与内核「单写者约定」正交：那条说的是**落盘存档**只许一个写者，别互相引用当证明

## 故意不给 agent 的（能力有，但只许人做）

| 操作 | 为什么 |
|---|---|
| **永久删除节点** | `undo` 只做**临时**删并恢复。永久删记忆是人的动作 —— 与 `clear` 同一条纪律：删除只有一条路，且要人显式走 |
| **清空使用记录** | 同上。清空 = 抹掉「越用越顺手」的全部依据 |
| **改已冻结的透镜（force）** | 换透镜必须显式 `force`；`ask` 自动冻只在**没有**透镜时发生。悄悄换透镜与主动换，在读到的树上长得一样 |

## 一句总结

八件工具里，**四件是动作**（orient / ask / remember / drill）、**四件是能力**（derive / remember_answer / undo / next）。

## 答案缓存（2026-10-24）：级联 + 编译

「先查树，不命中才问 agent，答完编回树」—— 对应两条成熟路子：
**FrugalGPT(2023) 的 LLM cascade**（便宜先上，不行才升级；RouteLLM 报成本降 85%、质量留 95%）
+ **Soar 的 chunking**（把求解经验编进长期记忆，避免重解）。

| 旧顾虑 | 现成解法（都在系统里） |
|---|---|
| 模型代填 | **允许**（README 第 75 行早有：模型可以填内容，每块带出处、三类分开可筛）|
| 标记 | `filled_by: agent` + `derived_from`，永不进「已验证」|
| 过期 | 键 = 问题；**语料指纹写在文件里**，查找时比对 ⇒ 明说「已过期，不采用」|
| 可回滚 | 删掉那个 json 即逐字回退 |
| 误命中 | `from_cache: true` 单独一栏，不混在材料答案里 |

⚠️ 键**不含**指纹：含了就变成「找不到文件」，与「从来没有过缓存」长得一样 ——
看不出「有缓存但过期了」。
砍掉的是仪式（原先把「提议 → 冻结 → 查 → 看状态」四步摊在 agent 面前），
补回的是能力（派生维度、反事实、反思 —— 内核早就有，插件原来够不着）。
**真人的步数始终是零。**

## 否定闭环（2026-10-25，外部评审 C1 / C2 / D1 接上）

内核 v0.1.39 起，三件在**产品路径**上闭环 —— 不是只写机制：

```
人 drill(verdict="wrong")  ⇒ outcome = -1（倾向当场刷新，不等下次启动）
   ⇒ 支的倾向变负
   ⇒ ask(reject_below=N)   ⇒ 倾向 < N 且 require 不含该支 must ⇒ 不摆出来
                            ⇒ skipped_rejected / rejected_items（差额可算）
   ⇒ require 说全（含该支 must）⇒ 那支回来（明确问到，不跳）
```

| 分工 | 谁做 | 改候选集吗 | 在哪 |
|---|---|---|---|
| **项级**（这一条被推翻） | 材料 front matter 的 `verdict` ⇒ `answer_verdicts` | **不改**（照常返回，带标记，判断权交调用方） | `entry.query` |
| **支级**（这一支被推翻） | `reject_below` 阈值（**外生**） | 改（不摆出来 + 报差额） | `entry._rejected_dirs` |

⚠️ **判错只能外部授予**：`actor != human` 一律拒 —— agent 只能提议待核。
   ⚠️ `actor` 与 `filled_by` 同款：**调用方声明，服务器不验身份**。守的是
   「接口不发给 agent」，不是「能证明是人」。
⚠️ **阈值不许自己发明**：`reject_below` 由调用方/透镜声明，不传 ⇒ 一条都不跳
   （与从前逐字相同）。
⚠️ **跳过必须报差额**：`n_answer + rejected_items == 不跳时的 n_answer`。
   静默改变候选集是本仓库最忌的形状（`kernel.py:851` 的假阴警告）。
⚠️ **越具体的问题，权重机制越不起作用**：倾向排序只在多支时发生；单支查询里
   被否定的那支照样是唯一答案 —— 要真的不返回它，用 `reject_below`。

判据：内核侧 `[否定]` 九条（含**反向对照**：把 `_rejected_dirs` 打成返回空
⇒ 带阈值也必须一条都不跳）；本仓库 **S36a–S36d** 验同一条链在 MCP 路径上闭环。

## 真实使用流程检验（2026-10-25）：`probes/real_usage.py`

与 `smoke_test.py` 的分工：**smoke 守点（每条判据一个承诺），这个探针走线（一条完整轨迹）+ 铺面（26 条边缘）**。

    轨迹 F01–F12   空库 → 写三条 → 查 → 下钻 → 派生 → 反事实 → 编译答案 →
                   语料变 → 缓存过期 → 判错 → 支级跳过 → 收尾对账
    边缘 E01–E26   未知键 / 零命中 / limit 0 与超大 / max_chars 0 与 1 / 句柄越界与跨查询 /
                   不存在 did / 坏 verdict / undo 编造 id / derive 空值与编造 id 与同名重建 /
                   同 id 覆写 / 空正文 / 5000 字正文 / forbid / max_branches /
                   多语料隔离 / 不存在的语料 / 无负事件时 reject_below
    确定性 D01     整条轨迹在**三个独立 store** 上各跑一遍，读数必须逐字相同

### 这一轮挖到的三个**真问题**（都已修）

1. **缓存过期用错了指纹** —— 原来用 `app.fingerprint()`，那是**结构票据**
   （项数 / 键数 / 方向数，**不含正文**）⇒ 改一条笔记的正文，缓存**不失效**，
   `from_cache` 仍是 True、`cache_note` 是 None。
   这正是「过期缓存静默赢过新答案」那个失效模式。
   ⇒ 缓存改用 `_content_fp()`（相对路径 + 字节数 + mtime）。
   ⚠️ 两个用途要**两个**指纹：透镜问「切分还成立吗」（不含正文是对的），
   缓存问「答案还是这个吗」（必须含正文）。

2. **点号字段的两种写法不等价** —— `keys_of()` 只认**嵌套**写法
   （`source:/n  kind: x`）；平铺写法（`source.kind: x`）的**值不进词汇表**，
   查 `source.kind=论文` 会报「未知键」。
   ⇒ 内核 `ENUM_FIELDS` 加 `source.kind`（判据 `[否定] ⑧` 守两种写法等价）。

3. **`max_chars=0` 被 `or` 吞成 2000** —— `a.get("max_chars") or 2000`，0 是 falsy
   ⇒ 「我只要 0 字」变成「给我 2000 字」，**静默改变用户意图**。
   ⇒ 显式给 0 ⇒ 正文空，且 `truncated=False`（没少给东西，是没要）。

### 两条**语义**（不是 bug，但必须写明）

1. **判错一次压不过历史正记录**：倾向是**累计**的（`+3` 次有用、`-1` 次判错 ⇒ 净 `+2`），
   所以 `reject_below=0` 时**不会跳**。这是「多数说了算」，不是漏跳。
   要「判错即失效」，阈值要按自己的累计量级定，或者先把正记录清掉。
2. **句柄表每次 `ask` 覆盖**：连问两问之后用旧编号做动作会被拒
   （「句柄属于另一次查询」）。这是**正确**行为（防静默指错），但顺序敏感 ——
   动作前先按同样的 `require` 再 `ask` 一次。

### 探针自己错了四次（都是「期望写错」，不是产品错）

忘了空库自带 1 项「基石」（项数全差 1 —— 那条设计 2026-10-25 已删）｜忘了句柄表会被后一次 ask 覆盖｜
错误返回有**两种形状**（`ok=False` 与 `{"_raw":…}`，第三次踩）｜
用了一个**值不在词汇表**的键去造「零命中」（走的是「未知键」另一条路）。

## 自己的产物进结构（2026-10-25，评估补的那一环）

`认知原型.md` 第三句承诺：「它能**包含自己** —— 自己的产物标成 `我=是` 进结构，
于是反思与重构是可查询的项」。这句在**两个仓库里指的是两件事**：

| | 「自己」是谁 | 怎么进结构 | 状态 |
|---|---|---|---|
| **repo** | 这个**软件的文档与断言**（`docs/形式化断言集.md`、`docs/*.md`、`README.md`） | `make_self_corpus` 机械抽取（字段全来自已有文字），判据 `[自我] ⑴⑵` 守「自描述一致 + 能回答自己」 | ✅ 早已完善 |
| **MCP** | **AI 的运行时回答** | `remember_answer` 原来只写 `answers/*.json` 缓存 ⇒ 查不到、不参与 `next`、不参与反思 | ✅ 2026-10-25 接上 |

### 为什么当初没接

不是漏，是**两边的「自己」不是同一个东西**：
`make_self_corpus` 的输入是 `docs/` 与 `README.md`（仓库里的文件），
而 MCP 的 store 里没有这些 —— 硬接等于把**产品文档**塞进**用户的库**。
MCP 需要的是另一条路：AI 运行时写的东西（回答、判断）自己进结构。

### 现在的形态

```
remember_answer(require, answer, source)
   ├─ answers/<key>.json   缓存（下次同类问题先命中；语料变/记录删 ⇒ 作废）
   └─ nodes/ans-<key>.md   结构里的一项：type=回答｜我=是｜filled_by=agent
                           ｜evidence_status=未验证｜source 指回材料
```

四条判据 **S38a–d**：
① 答完 ⇒ `我=是` / `type=回答` 都查得到，正文就是 AI 写的那段
② **写自己的记录不让答案缓存失效**（它是对材料的回答，不是材料 ——
   `_content_fp` 跳过 `ans-*`；第一版没跳，刚写完缓存立刻过期，实测踩到）
③ 同键再答 ⇒ 写新版 `-2`，**不覆写**旧记录（「我改过想法」是反思的材料）
④ 删掉那条记录 ⇒ 缓存**作废并说明**（记忆删了，答案不能还在）

⚠️ **`evidence_status` 恒为「未验证」**：AI 自己写的回答永远是这个状态，
   要「已验证」只能外部授予 —— 与 `drill(verdict=wrong)` 只能人给是同一条纪律。
⚠️ **没有删节点的工具**：`undo` 是「只算不改」（反事实预测），
   要真删只能手工删文件。这是有意的（删记忆是人的事）。

## 推理闭环有判据了（2026-10-25，S39a–e）

定位上说「推理 = 失配驱动的结构修复」。这句话在 2026-10-25 之前**没有判据守着**：
三种失配各有判据、改结构有账（`§S4`），但**「改完失配真的没了吗」没人守** ——
那个闭环只在文档里跑过，没在判据里跑过。

现在 `S39a–e` 守它，**⑤ 是反向对照**：

```
① ask 一个词汇表里没有的键 ⇒ out_of_structure + can_agent_fill
⑤ **不 derive 再问一次 ⇒ 必须仍然 out_of_structure**（否则 ②④ 读同一个来源，空转）
② derive 造维度 ⇒ 结构多了这个维度
③ 同一个 ask ⇒ 不再超出结构，且答得出
④ next 的 `失配.结构坏了 == 0` ⇒ 修复没把结构弄坏
```

内核侧对应断言 **`§S6` 失配修复收敛**（陈述 / 前提 / 三步证明 / 最小反例 / 落点）：
可达（`keys_of` 定义 + 派生叠加）、有限（维度有限、`rank` 严格增）、不破坏不变量
（`derive` 只追加 keys、`expand` 只切成员）。

⚠️ **`§S6` 证的是「改结构能收敛」，不是「推理正确」** —— 系统不知道某个维度该不该
存在，那是人的判断（`§D1` 外生准入）。它只说：**一旦决定加这个维度，失配必然消失，
且不会把结构弄坏。**

真实轨迹里也有一步：`probes/real_usage.py` 的 **F14**（失配 → 反向 → derive → 满足 → 自洽）。

## 为什么「规则」不进结构（2026-10-25，用户裁定）

曾经考虑过把「什么情况下怎么切」写成节点（`type=规则`），让 agent 查得到
「我为什么这么分」。**用户否掉了，理由是对的**：

> 「AI 不需要知道规则啊，它只翻译不行吗，这些规则系统里已经处理过了没必要再交给 agent 呀」

三条理由，一条比一条硬：

1. **分工**：agent 的活是**翻译**（自然语言 → 键）。结构怎么切、规则怎么定，
   是系统的内部实现。**接口暴露「能做什么」，不暴露「怎么做的」** ——
   把规则交出去是把实现细节泄漏给调用方。
2. **它也用不了**：agent 改不了代码，看得到规则也改不动 ⇒ 知道了只会多一个
   可能被误引用的东西（「我按规则 X 做的」——而规则 X 已经变了）。
3. **可审计不靠它**：规则的可审计性靠**代码 + 判据**（`B` 系列、`§K` 系列守着
   切分的正确性），不靠「规则变成一条可查的项」。

⇒ 这条**已裁定不做**（不是「做不了」，是「不该做」）。记在这里，免得下次又提。

## 程序性记忆：**在结构里**（2026-10-26 修正）

上一版评估把「程序性记忆」记成缺失，理由是「插件是人写的代码，经验不改它」。**这是错的。**

`Direction` 有四个字段，其中三个**就是规则本身**：

```
D3  rank=3  origin=split  parent=D2
    payload = (require {type=概念}, forbid {type=判断点})
```

| 字段 | 它记的是 |
|---|---|
| `payload` | **这一支是按哪一刀分的**（键集 / 锚点集） |
| `origin` | 这一刀的来源：外生声明 / 切分 / 涌现 |
| `parent` | 它是从哪一支切出来的（`rank` 严格增，向上指） |

⇒ **「什么情况下怎么切」不是只在代码里 —— 每一次真的切了，都落在节点上。**
代码里只有**可用的切法有哪几种**（插件的能力），
**实际切了哪一刀、切出什么** 在结构里，且随 `expand` 累积。

⚠️ **它不交给 agent 是有意的**（用户裁定）：agent 的活是**翻译**（自然语言 → 键），
规则是系统内部实现 —— 接口暴露「能做什么」，不暴露「怎么做的」。
**「不交给 agent」≠「没有」。** 这两件事上一版被混成了一件。

## 缓冲命中率：三个口径，四个工作负载（2026-10-26 实测）

**为什么不能只报一个数**：命中率完全取决于**问题重复率**。同一问连问五次是 80%，
每问都不同是 0% —— 报一个不带工作负载的「命中率」是剧场。

| 口径 | 算法 | 它回答什么 | 实测 |
|---|---|---|---|
| **答案缓存命中率** | 命中 / `ask` | 省了多少次问 agent | 见下表 |
| **缓冲曝光命中率** | `promoted` / 摆出的支 | 摆出的支多少**被证明有用** | 1/7 = 14% |
| **漏检率** | 重新提到 / 挤出数 | 会话缓冲挤错了多少 | `None`（还没挤掉过） |

```
W1 同一问连问 5 次            ask= 5 命中= 4  80%
W2 每问都不同（探索型）        ask= 5 命中= 0   0%
W3 真实轨迹（8 新 + 4 回头）   ask=12 命中= 4  33%
W4 语料变了之后重问           ask= 3 命中= 0   0%   ← 作废，不是 bug
```

⇒ **它是复用率，不是智能指标。** 别拿它当能力读数（这一条写进 `orient.cache` 的 note 里）。

### 键的等价性（命中率被无谓压低的地方）

| 写法 | 等价吗 | 说明 |
|---|---|---|
| 换顺序 `['b','a']` vs `['a','b']` | ✅ 等价 | `_cache_key` 里 `sorted` 过 |
| 等号带空格 `type = 立场` | ❌ **不等价** | 被当成**未知键**（`out_of_structure`），不是同一个问题 |
| 字段名大写 `Type=立场` | ❌ 不等价 | 键名区分大小写 |

⚠️ 空白那条**没改**：改它等于改查询语义（要不要容忍空白是语义决定，不是 bug）。
现在它会报「这些键不在词汇表里 —— 可能是拼错了」，信息是诚实的。

### 判据 `S41a–c`

| 编号 | 守什么 |
|---|---|
| `S41a` | 一次都没问 ⇒ 命中率是 **`None`**，不是 `0` |
| `S41b` | 问 2 次命中 1 次 ⇒ 报 `ask=2 命中=1 率=0.5` |
| `S41c` | **反向对照**：往日志塞一条**老格式**（没有 `cached` 字段）的 ask ⇒ **不进分母** |

★ `S41c` 是这条读数的关键：`cached` 字段是这版才加的，**老日志里没有**。
拿「没记」当「没命中」会把命中率算低 —— 与「有字段 ≠ 有读数」是同一类坑，
所以「没记 ≠ 没命中」必须由判据守，不能只写在注释里。

## 标注 vs 状态：`filled_by` 不是闸，`evidence_status` 才是（2026-10-26，S42a–d）

### 洞（实测）

```
remember(fields={"evidence_status":"已验证"})   ← 由 agent 调用
⇒ ok=True，落盘 front matter 里真的写着  evidence_status: "已验证"
```

「『已验证』只能外部授予」是 `§S5`、README、认知原型反复写的红线。
agent 一句话就能把它写进节点 ⇒ **它可以给自己发证书**。

### ★ 为什么一直没被发现：判据只守了源码那一半

```
★ [外部授予] 系统源码里没有把节点标成「已验证」的字符串字面量（docstring 不算）
```

它扫的是**系统自己的源码**，证明「系统不会主动写」——这条是对的，也一直在跑。
而洞走的是**调用方数据通道**（`fields` 透传）：源码里一个 `已验证` 字面量都没有
⇒ **判据照样绿**。⇒ **承诺 ≠ 判据覆盖。**

### ★★ 分界（用户纠正过一次，第一版做错了）

第一版把 `filled_by` 也做成了闸（agent 写 `human` ⇒ 拒）。**方向错了**：

> 「使用是不在乎这条数据由谁填充，直接进入并且使用，但是人的填充特意标注，给与特殊的地位」

| 字段 | 它是什么 | 设闸吗 |
|---|---|---|
| `filled_by` | **来源标注**（谁填的） | ❌ **不设** —— 使用不看来源 |
| `evidence_status` | **状态结论**（验没验过） | ✅ 只有 `actor=human` 能给 |

⇒ **标注不设闸，特权设闸。** 把标注也做成闸，等于「使用」前先查资格 —— 那就不是使用了。
「人的填充给特殊地位」的落点是：**`human` 是唯一能承载「已验证」的来源**。

### 修法

```python
HUMAN_ONLY_VALUES = {"evidence_status": {"已验证"}}   # ⚠️ 没有 filled_by

def _stamp_provenance(actor, fields, filled_by) -> str:
    # ① filled_by 只能记成你自己的 actor —— 不是「没资格写 human」，
    #    是「不能替别人声明来源」
    # ② evidence_status=已验证 只有 actor=human 能给
    # ③ 其余一律放行
```

`_stamp_provenance` 在**落盘之前**判 —— 不是写完再改，那会留下一条脏记录。

| 三条纪律 | 为什么 |
|---|---|
| **`filled_by` 是通道盖的章，不是调用方填的表** | 标注要可信，就不能由被标注者自己填 |
| **拒，不降级** | 降级要猜调用方意图（「你其实想写 agent 吧？」）—— 而这两个值是**结论**，结论不能猜 |
| **`remember` 补 `actor` 参数** | 原来它没有 `actor`，闸会把人一起拦死 —— 那样「反向对照」根本测不出来（等于恒拒） |

### 判据 `S42a–d`（两条正向 + 三条反向对照）

| 编号 | 守什么 |
|---|---|
| `S42a` | agent 声称「已验证」⇒ 拒，**且一个字节都没落盘** |
| `S42b` | agent 写 `filled_by=human` ⇒ 拒（不能替别人声明来源） |
| `S42b2` | agent 写 `filled_by=agent`（等于自己的 actor）⇒ **允许**（闸不许误伤） |
| `S42c` | **反向对照**：`actor=human` 声称「已验证」⇒ **接受** |
| `S42d` | **反向对照**：agent 写「未验证」⇒ **允许**（闸不许做过头） |

★ 三条反向对照是这条闸的**全部价值**：没有 `S42c`，一个「永远拒」的实现也能过 `a/b`；
没有 `S42b2`，把「写自己来源」也拦掉同样能过；没有 `S42d`，把正常写入也拦掉同样能过。
**「拒得对」必须和「该收的收了」一起判。**

### 边界

**这是声明式信任，不是认证。** 调用方写 `actor=human` 就能过闸 ——
服务器不验身份（`README` 已写明这个模型）。
它挡住的是「agent 顺手给自己发证书」，挡不住「刻意冒充人」。
真要挡后者，得把 `已验证` 的授予挪到 MCP 通道之外（人直接改文件）。

## 变更回执：本会话改了哪几处（2026-10-26，S43a–d）

### 为什么要有它

`orient.recent_calls` 只取最近 **5 行**，而且**混着读操作** —— 实跑一次：

```
['orient', 'remember', 'remember', 'ask', 'drill']
```

写被读稀释掉了。agent 做完一串事，人**看不出它动了什么**，得自己去拼
`log/mcp-calls.jsonl`。

### 三个实测障碍（都修了）

| 障碍 | 修法 |
|---|---|
| 写操作**不接受 `session`**（`remember` / `derive` / `remember_answer` 参数里没有）⇒ 归不到会话 | 三个工具的 schema 补 `session` |
| 日志行**没有独立 `session` 字段**（只有 `args.session`，而写操作根本不传） | `_log_call` 单独记一列（空串也记 ⇒ 漏了看得出来） |
| 回执**没有身份**：`remember` 失败时也进日志，分不清「写成了」与「同 id 被拒」 | summary 补 `written` / `key`；回执只收**成功**的写 |

### 回执长什么样

```json
"changes": {
  "新写": ["c1", "c2"],
  "造维度": ["proj"],
  "编译答案": [],
  "降权支": ["D1"],
  "合计": 4,
  "scope": "session:rcpt-1"
}
```

| 规则 | 为什么 |
|---|---|
| **只收写** | `orient` / `ask` 不改任何东西，混进来就是噪声 |
| **降权算变更** | `drill(verdict="wrong")` 改的是倾向，不是读 |
| **只收成功** | 否则「写失败三次」和「写成功一次」长得一样 |
| **去重** | 同一条被提及多次只点名一次（回执是「改了哪几处」，不是「调了几次」） |
| **不带 `session` ⇒ `scope` 明说「这不是本次」** | 否则一次「全部历史」会被读成「本次会话」—— 静默的误读 |

### 判据 `S43a–d`

| 编号 | 守什么 |
|---|---|
| `S43a` | 本会话的写点得出名，**别的会话的不混进来** |
| `S43b` | 造维度与降权支也进回执（降权算变更） |
| `S43c` | **反向对照**：读操作（`ask` / `orient`）**一条都不进回执** |
| `S43d` | 不带 `session` ⇒ 汇总全部，但 `scope` 明说「不是本次」 |

★ `S43c` 是这条回执的**存在理由**：没有它，回执就是 `recent_calls` 换了个名字 ——
把读也算进去，等于没做这件事。

## 字段性质清单：哪些是结论、闸在哪、**有没有消费点**（2026-10-26）

用户定：「这三个都是结论啊，都有闸在守而且是划分的判据」——
`derived_from` / `rationale` / `origin`。核对结果：**性质判断对，闸也都在**，
但读取侧漏了一处，见下表最后一行。

| 字段 | 性质 | 闸（**写**侧） | 消费点（**读**侧） | 状态 |
|---|---|---|---|---|
| `evidence_status` | **结论** | `_stamp_provenance`：`已验证` 只有 `actor=human` 能给 | 可作键筛（`evidence_status=已验证`）+ `orient.value_counts` | ✅ 两侧都在 |
| `filled_by` | 标注 | 只能等于自己的 `actor`（通道盖章） | `provenance.buckets` 分桶 | ✅ |
| `verdict`（项级） | **结论** | `drill(verdict="wrong")` 只收 `actor=human` | `ask.answer_verdicts` | ✅ |
| `origin`（方向） | **结论**（划分的判据） | `Direction.__post_init__`：枚举 + **外生不许有父** ⇒ 切出来的方向**不可能**声称外生 | persist 往返 / snapshot 报告 / `§K9` 的行为判据 `F3`（外生项指纹未变） | ✅ 闸是**结构性**的，最硬 |
| `rationale`（透镜） | **结论** | `spec` 必填 | `orient.lens.rationale` **报出来** | ✅ |
| `what` / `why` / `derived_from` / `generated_by` / `derived_at`（派生维度 sidecar 的 `_meta`） | **结论** | `derive` 必填非空（`rationale`、`derived_from`） | ❌ **`entry.py` 只读 `_meta["field"]` 与 `values`** | ⚠️ **只写不读** |

### ⚠️ 最后一行是个真缺口

```python
# entry.py 加载派生维度
field, vals = str(doc["_meta"]["field"]), doc["values"]   # ← 只取这两个
```

`_meta` 里写着 6 个字段，**只有 `field` 被读**。`what` / `why` / `derived_from` /
`generated_by` / `derived_at` 写进去之后**没有任何读取路径**。

后果有两层，第二层更要紧：

1. **`derive` 的 docstring 说「`derived_from` 决定答案里敢不敢把它当事实」—— 目前没有代码兑现这句话。**
   它既不参与筛选，也不出现在 `ask` / `orient` 的输出里。
2. **用户被要求必填一个理由，写完就没了。** 而「必填」是有代价的（agent 得编一段
   说得过去的话才能建维度）—— 收了这个代价却不用它，等于只收了税没修路。

⇒ 与「有字段 ≠ 有读数」「承诺 ≠ 判据覆盖」是**同一类**：这次是「**有闸 ≠ 有消费**」。

| 编号 | 守什么 |

|---|---|---|
| L1 维度不存在 | 问「下载量」（材料没这字段） | `out_of_structure` ⇒ 挡得住 10/10 |
| L2 取值不存在 | `py=4.0` | `out_of_structure` ⇒ 挡得住 10/10 |
| **L3 项存在、内容没有** | 问「pandas 的下载量」 | `n_answer>0` ⇒ **挡不住** |

L3 的失败路径是：agent 拿到项 → **不再问 ldv**（问了也问不出，「下载量」不是键）
→ 自己从项里找 → 找不到 → **编一个**。

⇒ **ldv 没有机会发言，不是它不肯。** 它已经答完了。

### 但「挡不住」不等于「只能编」

原来 agent 只有两条路：**给个答案**，或者**沉默**。而沉默在结构里不留痕 ——
于是它倾向于编。补的是一条正式出口：

```python
remember_answer(corpus=…, require=…, unknown=True,
                why="材料里没有「下载量」这个字段（字段只有 type/scope/notes/source/…）")
```

弃答于是变成**一条结论**，而不是「没说话」：

| 性质 | 怎么做到 |
|---|---|
| **可查** | 节点 `type=未答`（不是 `回答`）⇒ `ask(require=["type=未答"])` 筛得出来 |
| **可复核** | `why` **必填** —— 不说清「缺什么」的弃答是「哑」，不是「弃答」 |
| **可纠正** | 同键再答一次正常答案 ⇒ `unknown` 翻回 `false`（弃答不是终局） |
| **不会被误当答案** | 命中时 `cached_answer` 单独报 `unknown: true` + `why`，note 明说「这是上次的弃答判定，不是答案」 |

### 判据 `S46a–d`

| 编号 | 守什么 |
|---|---|
| `S46a` | 弃答写得进去，节点记成 `type=未答` |
| `S46b` | 再问 ⇒ 命中并**明确报** `unknown: true` + `why` |
| `S46c` | **反向对照**：`unknown=true` 但不给 `why` ⇒ 拒 |
| `S46d` | 弃答变成可查的项（`type=未答` 筛得出来） |

探针侧另有 `L5a–c`：10 道 L3 题全记成弃答、筛得出来、同键再答能翻回来。

### 一句话

**没有出口时它只能编；有了出口，编就只是「没走出口」—— 那是 agent 的事，能判。**
