# 能力对账：内核能做的 vs 插件暴露的

> 2026-10-24 ｜ 原则（用户定）：**打包成插件只舍弃自由度，不牺牲能力。**

这张表是那条原则的账本。每一行写清：内核有、插件有没有、没有的话**是舍弃能力还是舍弃自由度**。

## 已暴露（八件工具）

| 内核能力 | 插件工具 | 说明 |
|---|---|---|
| 装载语料、算键集 | `orient` | 只读；`_data/<名字>/nodes` 是唯一真相源 |
| 在树上查一支（分区不重不漏） | `ask` | 键先过词汇表；支序原样 |
| 下钻 = 有用（两段通道） | `drill` | 记录只改次序，答案集合逐字不变 |
| 写入节点（`insert`） | `remember` | **只追加不覆写**（覆写就是改写记忆） |
| **派生维度**（`derived/*.json`，v0.1.36 的 `influence` 就是它） | `derive` | 不写回材料；删 sidecar 即逐字回退 |
| **反事实**（`core/impact.py`：`removal_impact` / `compare_prediction`） | `undo` | 答案集的变化**算出来**（`App.answer_set` 只由键决定 ⇒ 删一项只能丢掉它）；结构侧在**深拷贝**上真删（内核自己要求「给一份深拷贝」）⇒ 不需要恢复，**「恢复失败」这个红状态直接消失** |
| **反思**（`reflect.graded`，动机三档） | `next` | 按后果分档，不是分数 |
| **节点的标题与正文** | `ask`（默认） | 正文是主产物 ⇒ 默认给；`structure=true` 才连分支与谓词一起给 |
| **条目的身份（id）** | 本地 `handles.json` | agent 只看到**句柄**（第 n 条）；动作说 `n`，服务端查本地表换成 id —— 记录留在 ldv，agent 不背它 |

## 未暴露 —— 是「舍弃自由度」，不是「牺牲能力」

| 内核能力 | 为什么不做成工具 |
|---|---|
| 落盘 / 内核快照（`persist` / `snapshot`） | 内核快照是**可重建的缓存**。暴露它 = 多一个会漂的真相源（存档与语料不同步时，谁对？）。产品的真相源只有两个：语料、`derived/` |
| 建树计划 / 续建（`--plan` / `--snapshot` / `--plan-all`） | 同上：那是「把一棵树分几次建完」的调度，不是新能力。插件按需建，agent 不需要知道分几步 |
| 视图层（`view_spec` + `recognize`） | 产品层的对应物是**透镜**（`ask` 的 `lens`）。两套并存会让人分不清「哪个在定义方向」 |
| `ldv-msg/1` 协议（ldv ↔ ldv） | 那是两个内核之间的对讲。插件是「内核 ↔ agent」，不是同一件事 |
| 服务壳（`serve.py` 多租户 / 队列） | 另一个产品面。MCP 宿主自己就是那个壳 |
| 并发锁壳（`--locked`） | 内核那把锁护的是**一个进程内的内核对象**；产品这一层不需要它 —— 每次调用都新建一个 `App`，进程内本来串行。**跨进程**（两个会话指向同一 store）由产品自己的写锁护，见下 |

## 跨进程写：已经补上了（2026-10-24）

原来这条是账本里唯一标红的：两个宿主会话指向同一个 store 时，
`remember` / `derive` / `freeze` 的「先查再写」会互相踩 —— 两边都看到「没有」，
两边都写，后写的赢且**没有任何信号**。现在：

| 机制 | 在哪 |
|---|---|
| **写锁**（`O_CREAT\|O_EXCL` 抢 `.lock`，拿不到 ⇒ `StoreBusy`） | `checks/lock.py`；`remember` / `derive` / 自动冻结三处持锁 |
| **原子创建**（`create_exclusive`，已存在 ⇒ False，不 TOCTOU） | `remember`（同 id 双写只有一个成功） |
| **不许静默覆盖**（同名派生维度第二次必须拒，要换显式 `force`） | `derive` |
| **陈旧锁接管**（mtime 超 120 秒视为进程已死，抢过来并记 `_stale.txt`） | `checks/lock.py` |

⚠️ **边界说清楚**：
- 锁护**写**不护**读** —— 写是原子的（`os.replace`），读到的要么是旧的要么是新的
- 这是**本机写锁**，不是分布式锁：NFS / 网络盘上 `O_EXCL` 的语义不保证
- 被杀进程会留下 `.lock`，要等 120 秒接管 —— **这是设计，不是 bug**
  （判据 S18b 专门验这个遗留）
- 与内核「单写者约定」正交：那条说的是**落盘存档**只许一个写者，别互相引用当证明

## 故意不给 agent 的（能力有，但只许人做）

| 操作 | 为什么 |
|---|---|
| **永久删除节点** | `undo` 只做**临时**删并恢复。永久删记忆是人的动作 —— 与 `clear` 同一条纪律：删除只有一条路，且要人显式走 |
| **清空使用记录** | 同上。清空 = 抹掉「越用越顺手」的全部依据 |
| **改已冻结的透镜（force）** | 换透镜必须显式 `force`；`ask` 自动冻只在**没有**透镜时发生。悄悄换透镜与主动换，在读到的树上长得一样 |

## 一句总结

八件工具里，**四件是动作**（orient / ask / remember / drill）、**四件是能力**（derive / remember_answer / undo / next）。

## 答案缓存（2026-10-24）：级联 + 编译

「先查树，不命中才问 agent，答完编回树」—— 对应两条成熟路子：
**FrugalGPT(2023) 的 LLM cascade**（便宜先上，不行才升级；RouteLLM 报成本降 85%、质量留 95%）
+ **Soar 的 chunking**（把求解经验编进长期记忆，避免重解）。

| 旧顾虑 | 现成解法（都在系统里） |
|---|---|
| 模型代填 | **允许**（README 第 75 行早有：模型可以填内容，每块带出处、三类分开可筛）|
| 标记 | `filled_by: agent` + `derived_from`，永不进「已验证」|
| 过期 | 键 = 问题；**语料指纹写在文件里**，查找时比对 ⇒ 明说「已过期，不采用」|
| 可回滚 | 删掉那个 json 即逐字回退 |
| 误命中 | `from_cache: true` 单独一栏，不混在材料答案里 |

⚠️ 键**不含**指纹：含了就变成「找不到文件」，与「从来没有过缓存」长得一样 ——
看不出「有缓存但过期了」。
砍掉的是仪式（原先把「提议 → 冻结 → 查 → 看状态」四步摊在 agent 面前），
补回的是能力（派生维度、反事实、反思 —— 内核早就有，插件原来够不着）。
**真人的步数始终是零。**

## 否定闭环（2026-10-25，外部评审 C1 / C2 / D1 接上）

内核 v0.1.39 起，三件在**产品路径**上闭环 —— 不是只写机制：

```
人 drill(verdict="wrong")  ⇒ outcome = -1（倾向当场刷新，不等下次启动）
   ⇒ 支的倾向变负
   ⇒ ask(reject_below=N)   ⇒ 倾向 < N 且 require 不含该支 must ⇒ 不摆出来
                            ⇒ skipped_rejected / rejected_items（差额可算）
   ⇒ require 说全（含该支 must）⇒ 那支回来（明确问到，不跳）
```

| 分工 | 谁做 | 改候选集吗 | 在哪 |
|---|---|---|---|
| **项级**（这一条被推翻） | 材料 front matter 的 `verdict` ⇒ `answer_verdicts` | **不改**（照常返回，带标记，判断权交调用方） | `entry.query` |
| **支级**（这一支被推翻） | `reject_below` 阈值（**外生**） | 改（不摆出来 + 报差额） | `entry._rejected_dirs` |

⚠️ **判错只能外部授予**：`actor != human` 一律拒 —— agent 只能提议待核。
   ⚠️ `actor` 与 `filled_by` 同款：**调用方声明，服务器不验身份**。守的是
   「接口不发给 agent」，不是「能证明是人」。
⚠️ **阈值不许自己发明**：`reject_below` 由调用方/透镜声明，不传 ⇒ 一条都不跳
   （与从前逐字相同）。
⚠️ **跳过必须报差额**：`n_answer + rejected_items == 不跳时的 n_answer`。
   静默改变候选集是本仓库最忌的形状（`kernel.py:851` 的假阴警告）。
⚠️ **越具体的问题，权重机制越不起作用**：倾向排序只在多支时发生；单支查询里
   被否定的那支照样是唯一答案 —— 要真的不返回它，用 `reject_below`。

判据：内核侧 `[否定]` 九条（含**反向对照**：把 `_rejected_dirs` 打成返回空
⇒ 带阈值也必须一条都不跳）；本仓库 **S36a–S36d** 验同一条链在 MCP 路径上闭环。

## 真实使用流程检验（2026-10-25）：`probes/real_usage.py`

与 `smoke_test.py` 的分工：**smoke 守点（每条判据一个承诺），这个探针走线（一条完整轨迹）+ 铺面（26 条边缘）**。

    轨迹 F01–F12   空库 → 写三条 → 查 → 下钻 → 派生 → 反事实 → 编译答案 →
                   语料变 → 缓存过期 → 判错 → 支级跳过 → 收尾对账
    边缘 E01–E26   未知键 / 零命中 / limit 0 与超大 / max_chars 0 与 1 / 句柄越界与跨查询 /
                   不存在 did / 坏 verdict / undo 编造 id / derive 空值与编造 id 与同名重建 /
                   同 id 覆写 / 空正文 / 5000 字正文 / forbid / max_branches /
                   多语料隔离 / 不存在的语料 / 无负事件时 reject_below
    确定性 D01     整条轨迹在**三个独立 store** 上各跑一遍，读数必须逐字相同

### 这一轮挖到的三个**真问题**（都已修）

1. **缓存过期用错了指纹** —— 原来用 `app.fingerprint()`，那是**结构票据**
   （项数 / 键数 / 方向数，**不含正文**）⇒ 改一条笔记的正文，缓存**不失效**，
   `from_cache` 仍是 True、`cache_note` 是 None。
   这正是「过期缓存静默赢过新答案」那个失效模式。
   ⇒ 缓存改用 `_content_fp()`（相对路径 + 字节数 + mtime）。
   ⚠️ 两个用途要**两个**指纹：透镜问「切分还成立吗」（不含正文是对的），
   缓存问「答案还是这个吗」（必须含正文）。

2. **点号字段的两种写法不等价** —— `keys_of()` 只认**嵌套**写法
   （`source:/n  kind: x`）；平铺写法（`source.kind: x`）的**值不进词汇表**，
   查 `source.kind=论文` 会报「未知键」。
   ⇒ 内核 `ENUM_FIELDS` 加 `source.kind`（判据 `[否定] ⑧` 守两种写法等价）。

3. **`max_chars=0` 被 `or` 吞成 2000** —— `a.get("max_chars") or 2000`，0 是 falsy
   ⇒ 「我只要 0 字」变成「给我 2000 字」，**静默改变用户意图**。
   ⇒ 显式给 0 ⇒ 正文空，且 `truncated=False`（没少给东西，是没要）。

### 两条**语义**（不是 bug，但必须写明）

1. **判错一次压不过历史正记录**：倾向是**累计**的（`+3` 次有用、`-1` 次判错 ⇒ 净 `+2`），
   所以 `reject_below=0` 时**不会跳**。这是「多数说了算」，不是漏跳。
   要「判错即失效」，阈值要按自己的累计量级定，或者先把正记录清掉。
2. **句柄表每次 `ask` 覆盖**：连问两问之后用旧编号做动作会被拒
   （「句柄属于另一次查询」）。这是**正确**行为（防静默指错），但顺序敏感 ——
   动作前先按同样的 `require` 再 `ask` 一次。

### 探针自己错了四次（都是「期望写错」，不是产品错）

忘了空库自带 1 项「基石」（项数全差 1 —— 那条设计 2026-10-25 已删）｜忘了句柄表会被后一次 ask 覆盖｜
错误返回有**两种形状**（`ok=False` 与 `{"_raw":…}`，第三次踩）｜
用了一个**值不在词汇表**的键去造「零命中」（走的是「未知键」另一条路）。

## 自己的产物进结构（2026-10-25，评估补的那一环）

`认知原型.md` 第三句承诺：「它能**包含自己** —— 自己的产物标成 `我=是` 进结构，
于是反思与重构是可查询的项」。这句在**两个仓库里指的是两件事**：

| | 「自己」是谁 | 怎么进结构 | 状态 |
|---|---|---|---|
| **repo** | 这个**软件的文档与断言**（`docs/形式化断言集.md`、`docs/*.md`、`README.md`） | `make_self_corpus` 机械抽取（字段全来自已有文字），判据 `[自我] ⑴⑵` 守「自描述一致 + 能回答自己」 | ✅ 早已完善 |
| **MCP** | **AI 的运行时回答** | `remember_answer` 原来只写 `answers/*.json` 缓存 ⇒ 查不到、不参与 `next`、不参与反思 | ✅ 2026-10-25 接上 |

### 为什么当初没接

不是漏，是**两边的「自己」不是同一个东西**：
`make_self_corpus` 的输入是 `docs/` 与 `README.md`（仓库里的文件），
而 MCP 的 store 里没有这些 —— 硬接等于把**产品文档**塞进**用户的库**。
MCP 需要的是另一条路：AI 运行时写的东西（回答、判断）自己进结构。

### 现在的形态

```
remember_answer(require, answer, source)
   ├─ answers/<key>.json   缓存（下次同类问题先命中；语料变/记录删 ⇒ 作废）
   └─ nodes/ans-<key>.md   结构里的一项：type=回答｜我=是｜filled_by=agent
                           ｜evidence_status=未验证｜source 指回材料
```

四条判据 **S38a–d**：
① 答完 ⇒ `我=是` / `type=回答` 都查得到，正文就是 AI 写的那段
② **写自己的记录不让答案缓存失效**（它是对材料的回答，不是材料 ——
   `_content_fp` 跳过 `ans-*`；第一版没跳，刚写完缓存立刻过期，实测踩到）
③ 同键再答 ⇒ 写新版 `-2`，**不覆写**旧记录（「我改过想法」是反思的材料）
④ 删掉那条记录 ⇒ 缓存**作废并说明**（记忆删了，答案不能还在）

⚠️ **`evidence_status` 恒为「未验证」**：AI 自己写的回答永远是这个状态，
   要「已验证」只能外部授予 —— 与 `drill(verdict=wrong)` 只能人给是同一条纪律。
⚠️ **没有删节点的工具**：`undo` 是「只算不改」（反事实预测），
   要真删只能手工删文件。这是有意的（删记忆是人的事）。

## 推理闭环有判据了（2026-10-25，S39a–e）

定位上说「推理 = 失配驱动的结构修复」。这句话在 2026-10-25 之前**没有判据守着**：
三种失配各有判据、改结构有账（`§S4`），但**「改完失配真的没了吗」没人守** ——
那个闭环只在文档里跑过，没在判据里跑过。

现在 `S39a–e` 守它，**⑤ 是反向对照**：

```
① ask 一个词汇表里没有的键 ⇒ out_of_structure + can_agent_fill
⑤ **不 derive 再问一次 ⇒ 必须仍然 out_of_structure**（否则 ②④ 读同一个来源，空转）
② derive 造维度 ⇒ 结构多了这个维度
③ 同一个 ask ⇒ 不再超出结构，且答得出
④ next 的 `失配.结构坏了 == 0` ⇒ 修复没把结构弄坏
```

内核侧对应断言 **`§S6` 失配修复收敛**（陈述 / 前提 / 三步证明 / 最小反例 / 落点）：
可达（`keys_of` 定义 + 派生叠加）、有限（维度有限、`rank` 严格增）、不破坏不变量
（`derive` 只追加 keys、`expand` 只切成员）。

⚠️ **`§S6` 证的是「改结构能收敛」，不是「推理正确」** —— 系统不知道某个维度该不该
存在，那是人的判断（`§D1` 外生准入）。它只说：**一旦决定加这个维度，失配必然消失，
且不会把结构弄坏。**

真实轨迹里也有一步：`probes/real_usage.py` 的 **F14**（失配 → 反向 → derive → 满足 → 自洽）。
