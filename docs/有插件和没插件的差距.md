# 有插件 vs 没插件：回答差距实测

> 2026-10-24 ｜ 语料 = 内置 36 项（DAPO / GRPO / RL 训练）
> 探针：`probes/plugin_gap.py`，输出逐字留档 `probes/out/plugin_gap.out.txt`

## 实验怎么设计的

| | 条件 |
|---|---|
| **WITH** | 走插件：`orient` → `ask` → `drill`，答案带 node id 与出处 |
| **WITHOUT** | agent **凭自身权重**答：无工具、无语料、无记忆。答案在探针里**逐字记录，不许事后改** |

四条轴，都只报事实、不打分：**可指回性**（结论能否指到 node id）·
**捏造**（提到的节点语料里是否真有）· **覆盖**（语料实际有的找不找得到）·
**跨会话**（第一轮的记忆第二轮还在不在）。

## 逐字结果

### Q1「哪些立场还没验证？」

```
WITH    require=['type=立场','evidence_status=未验证'] ⇒ 3 项 / 1 支
        答案 id：['stance-0001', 'stance-0002', 'stance-0003']
        出处：{'模型(DeepSeek-V4.1-Flash)': 3}
WITHOUT 「未验证的立场有：DAPO 的长度归因、Dr.GRPO 的有偏优化质疑，
        以及几条关于 KL 惩罚该不该开的判断。」
```

坐实：KL 那条（`judge-0005-kl-penalty-on-or-off`）的类型是**判断点**，不是立场。
语料里立场**只有 3 条**，WITHOUT 说「几条关于 KL 的判断」也算进立场 —— **类型混淆**。

### Q2「有哪些议题？」

```
WITH    require=['type=议题'] ⇒ 2 项 / 2 支｜支序 ['D12','D16']
        答案 id：['issue-0001', 'issue-0002']
WITHOUT 「还没解决的分歧主要是：熵坍塌该不该管、优势组全零时怎么办、
        该用过程奖励还是格式奖励、以及长度惩罚加不加。」
```

坐实：WITHOUT 说的四件事**全是判断点**（`judge-0001/0002/0011/0012/0013`），
不是议题。语料真正的 2 条议题是「响应变长该归因于什么」「GRPO 是否真的不需要 critic」
—— **WITHOUT 覆盖 0/2，且把桶搞错了**。

### Q3「DAPO 相关的节点有哪些？」

```
WITH    require=['dapo=是'] ⇒ **拒收**：这些键不在词汇表里……
        ⇒ 词汇表里没有「主题」这个维度
WITHOUT 「立场节点讲它的四项技术，案例节点是它在 AIME 2024 上的结果，
        还有一个例外节点讲移除标准差代价的复现。」
```

**这一局 WITH 输。** 无插件侧凭知识联想，三条全对（`stance-0001` 四项技术、
`case-0001` AIME 2024、`exc-0001` 移除标准差）；有插件侧因为词汇表没有主题维度，
只能拒收。⇒ **语义联想是权重侧的本事，结构查询替不了它。**

### Q4「论文来源的节点有哪些？」

```
WITH    require=['source.kind=论文'] ⇒ 26 项 / 6 支
WITHOUT 「论文来源的节点有二十多个，主要是 DAPO、Dr.GRPO、GRPO 三篇的摘录。」
```

坐实：26 个论文来源节点引的 arXiv **至少 8 篇**（DAPO 7、DeepSeekMath 4+3、
Dr.GRPO 3、另有 3 个独立编号）——「三篇」是**自信而具体的错**。

### 跨会话（重建入口 = 新开一次对话）

```
WITH    读回使用记录 3 条｜覆盖方向 2 个｜ordered_by=usage
        第一轮钻过的支（D12）现在排在前面｜演员分解 3/3
WITHOUT  每次都从零开始 —— 它没有地方放第一轮钻过什么
```

## 四条轴的结论

| 轴 | WITHOUT | WITH |
|---|---|---|
| **可指回性** | 0 —— 没有语料可指，结论无法核 | 100% —— 每个答案带 node id |
| **捏造** | 3 处坐实（类型混淆 ×2、来源数错 ×1）| 结构上不可能（id 从语料来） |
| **覆盖** | 0/2 找到真议题 | 2/2 |
| **跨会话** | 无 | 有（记录 + 倾向 + 演员分解） |
| **语义联想** | **赢一局**（Q3） | 输（无主题维度，只能拒收） |

## 所以差距到底是什么

不是「有插件更聪明」，是三件事：

1. **无插件侧的错误不是胡说，是「词对、分类错、数量错」**—— 它对世界的知识大致成立，
   但对**这份语料的体系**一无所知（不知道 `type` 有 7 个取值、哪个桶装什么）。
   这类错误**看起来完全合理**，所以更危险。
2. **有插件侧换来的是可指回、可复现、有记忆**——代价是答不了词汇表没覆盖的问法
   （Q3），以及问之前必须先有人把维度建出来。
3. **正确的形态是叠加，不是二选一**：权重侧负责联想（「DAPO 相关」），
   插件负责落地（「语料里确实有这三条，id 是这三个」）。单有权重侧 = 流畅但不可核；
   单有插件 = 严谨但问不出来。

## 实验直接改掉了产品的一个缺口

无插件侧把「判断点」说成「议题」，根因是 agent **不知道语料的类型体系**——
`orient` 原来只给键名（`type`），不给取值分布（`type=议题` / `type=判断点` / …）。

⇒ `orient` 新增 `value_counts`（2026-10-24 落地）：

```json
{"type": {"判断点": 14, "概念": 8, "案例": 5, "立场": 3, "例外": 2, "议题": 2, "论据": 2},
 "evidence_status": {"未验证": 34, "有争议": 2},
 "source": {"论文": 26, "教材": 7, "官方文档": 2, "其他": 1}}
```

一条改进**不是**从这个实验推出的：词汇表没有「主题」维度（Q3 那局）。
该不该加 `topic` / `keywords` 字段是**语料作者的决定**（外生声明，系统不许自己编）——
产品只负责把「没有这个维度」说清楚，而不是替谁加一个。

## 怎么复现

```bash
python probes/plugin_gap.py     # WITH 侧实跑 + 真值对拍 + 跨会话
```

⚠️ WITHOUT 侧的答案**逐字钉在探针里**（`WITHOUT_ANSWERS`），改它就是改实验记录。
要重跑对照，换一批问题、换一个领域，重新逐字记录一遍。
