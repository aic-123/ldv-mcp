# 会话与多个 ldv：范围怎么切

> 2026-10-24 ｜ 判据 S22–S25 ｜ `checks/session.py`

## 三区（对话范围的三层，别混）

| 区 | 放什么 | 谁管 | 生命期 |
|---|---|---|---|
| **工作集** | 本轮推理的现场：刚才说的「第三支」指哪个、任务进行到哪 | **宿主**（不归插件） | 本轮对话 |
| **缓冲** | 这次会话「看到过什么」（曝光） | 插件，按会话隔离 | 有界，可丢弃 |
| **正式** | 明确「这条算数」的：语料 / `remember` / `derive` / 使用记录 | 插件 | 长期 |

★ 插件**替代不了工作集**，也不该替代 —— 上下文不只是存储，它是指代的锚点。
「按你说的那个改」这种话检索接不住，而且**检索漏了是静默的**。
插件替代的是**长期记忆**这一半。

## 缓冲里放什么（插件只看得到工具调用）

```
ask   ⇒ 一条曝光：这次摆出了哪几支、答案多少        （不是「有用」）
drill ⇒ 把对应曝光标成 promoted                     （这才是真实动作）
```

与内核的两段通道**同构**：查询只进缓冲，下钻才 promote。区别只在作用域 ——
内核按查询指纹，这里按**会话**。

## 有界、挤出、漏检率

缓冲有界（`config.json` 的 `buffer_cap`，默认 50），写满挤掉最老的。
**挤掉 ≠ 删除**：被挤掉的进 `evicted.json` 记账。

```
漏检率 = 被挤出后又被重新提到的次数 / 挤出总数
```

⚠️ **这个数一旦高，说明「拿插件替代上下文」在该场景不成立** —— 而且它是结构性证据，
不是感觉。实测（S23，cap=2）：挤出 1 条 ⇒ 漏检率 0.0；再问到被挤掉的那支 ⇒ 1.0。

`None` 表示还没挤掉过 —— **不是 0**（没发生过 ≠ 发生了 0 次）。

## 多个 ldv，一个 ldv 多个会话

```
store/
  _data/<ldv>/nodes           一个 ldv = 一套语料（一个「认识」）
  _data/<ldv>/derived/        它自己敲定的维度
  _data/<ldv>/usage/          使用记录（默认**跨会话**累积）
  _data/<ldv>/sessions/<sid>/ 会话缓冲（buffer.json + evicted.json）
  _data/<ldv>/config.json     {"buffer_cap": 50, "isolate_usage": false}
  specs/<ldv>/                透镜（按 ldv，不按会话）
  log/mcp-calls.jsonl         调用日志（每行带 actor；会话由参数体现）
```

- **`orient()` 不给 ldv 名** ⇒ 列出所有 ldv（只数文件，不建内核 —— 列目录不该付建树的代价）
- **`session` 由调用方声明**（默认 `default`），同 `actor` 的纪律：**照记不验**
- **`isolate_usage: true`** ⇒ 使用记录按会话隔离；**默认 false**（跨会话累积）

⚠️ 为什么默认 false：跨会话累积是**已有行为**。改默认值等于悄悄改变老用户看到的结果
（同一个问题，昨天钻过的支今天就不排前面了）。按「打包只舍弃自由度」，隔离是选项。
