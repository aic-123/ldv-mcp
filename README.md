# ldv-mcp

给 agent 装一个**会记住自己**的外挂。

语料装成一棵分层划分树，八件工具在树上查、钻、推、记。它**不生成内容、不打分、不排序** ——
只回答「这一带」，并说清凭什么。

内核 [`aic-123/ldv`](https://github.com/aic-123/ldv)（钉在 `v0.1.44`，见 `core/PINNED`）。
本仓库只包它，不改它。

---

## 它长什么样

三条笔记扔进去，问一句「我记得什么」：

```jsonc
// ask(require=[])
{
  "ok": true, "n_answer": 3,
  "items": [
    {"n": 1, "title": "DAPO 的损失聚合有问题",
     "text": "token 级平均把长回答的梯度摊薄了。", "fields": {"type": "立场"}},
    {"n": 2, "title": "长度惩罚与 clip-higher 会互相抵消",
     "text": "不能一起用。", "fields": {"type": "判断点"}},
    {"n": 3, "title": "batch=64 以上熵崩更快",
     "text": "这条在 alpha 上不成立。", "fields": {"type": "例外"}}
  ],
  "provenance": {
    "buckets": {"未标": 3}, "n": 3,
    "note": "三类分开可筛；「未标」= front matter 里没有 filled_by，不猜"
  }
}
```

注意三件事：

- **没有 `answer_ids`** —— id 留在本地，agent 只看到「第 n 条」。动作说 `n` 就行。
- **`provenance` 把出处分桶** —— 材料原有的、模型填的、agent 填的，三类不混。
- **没有分数、没有排序建议** —— 它不知道哪条「更重要」，也不该知道。

问一个它没有的维度：

```jsonc
// ask(require=["project=alpha"])  —— 词汇表里没有 project
{
  "ok": false,
  "out_of_structure": true,
  "unknown": ["project=alpha"],
  "suggest": {"project=alpha": ["scope", "notes"]},
  "can_agent_fill": true,
  "next_step": ["derive 一个维度（把这类取值建成可查的轴，带理由与来源）",
                "或映射到 vocabulary 里已有的键（换个问法）"]
}
```

**「这一格是空的」和「没有这个维度」是两件事**，它分开报。后者会告诉你：这是维度缺失，
agent 可以自己补一个（`derive`），补完再问就答得出 —— 这条闭环有判据（`S39a–e`，含反向对照）。

## 三条它坚持的事

每条都有判据守着，不是设计意图。

**① 不产内容。** 输出里每个字符串都能指回材料 —— 有一条判据逐字符串扫，
外加一条合成对照（故意塞一句无出处的话，必须被抓到）。判据 `§S1`。

**② 答案是位置，不是文本。** 没有命题、没有跨项标量。协议禁词 `score / weight / priority`
一出现就红 —— 一旦有分数，它就是推荐器，不是它了。判据 `§S2`。

**③ 它记得自己做过什么。** 钻过哪一支、判错过哪一支，都落在私人档案里，
下次同一问题支序就变。**最硬的证据是删掉 `usage/` 就全部回滚** ——
这条把「变化来自它自己的档案」和「变化来自模型随机性 / 缓存 / 上下文」分开了。
判据 `T1–T5`（[`docs/主体性判据.md`](docs/主体性判据.md)，1200 项 / 15 轮实测）。

## 三十秒起跑

```jsonc
// MCP 客户端配置（stdio）
{
  "mcpServers": {
    "ldv": {
      "command": "python",
      "args": ["/路径/到/ldv-mcp/server.py"],
      "env": { "LDV_MCP_STORE": "/路径/到/ldv-mcp/store" }
    }
  }
}
```

`LDV_MCP_STORE` 指向**一个空目录**就行 —— 空库直接能用（0 项，不写占位文件）。
把你的 md 语料放进 `store/_data/<名字>/nodes/`，不指就用内置 36 项。

然后**像平时一样问你的 agent**。它自己会 `orient`（我记得）→ `ask`（翻译 + 查）→
`drill`（有用）→ `remember`（记下来）；需要时 `derive`（造维度）、`undo`（删了会怎样）、
`next`（该干什么）。

### 这句要写进 agent 的系统提示

```text
回答之前先调用 ldv 的 orient（看看我记得什么、缺什么）；答完如果值得留，用 remember 记下来；
这次回答本身用 remember_answer 编进树（它会同时留一条「我=是」的记录）。
不确定的事说「不知道」，不要用记忆里没有的东西补。
```

不写也能用（工具都在），但「**先想起再答**」不会自己发生 —— MCP 是请求-响应，
服务端不能主动推。这是整套东西**唯一**需要使用者配合的地方。

## 读数（都是跑出来的，不是估的）

| | 数 |
|---|---|
| **成本**：每条答案 | 小规模 228 vs 135（RAG 基线，贵 1.69×）｜大规模 **61 vs 134（省 2.2×）** —— 库越大越值 |
| **位置偏差** | `context_recall = 1.00` —— 针放在语料哪个位置，命中率都不变（划分结构没有先后） |
| **确定性** | 同一轨迹在三个独立 store 上跑三遍，读数**逐字相同** |
| **连续性** | 它自己钻过 D1 ⇒ 同一问题 `ordered_by` 从 `default` 变 `usage`，D1 排第一（1200 项 / 15 轮：多支查询 2/2 变） |
| **独立度** | 换新进程仍复现 ✓；**删掉 `usage/` ⇒ 10 条查询全部回滚到基线** ✓ —— 变化来自私人档案，不是模型随机性 |
| **不是裁判** | 同一批 10 条查询，`answer_ids` / `n_answer` / `n_branches` **全同** —— 有视角，没有裁判权 |
| **判据** | 内核 885 条 + 产品 46 条 + 协议 8 条，全绿；新 clone 上同样全绿 |

成本那行的意思：小规模时插件比「把整库塞进上下文」贵，因为要付一次结构开销；
到 140 条笔记时反过来省一半以上 —— 它买的是**不用每次重读全库**。

还有一处它明确输：**同一会话里反复问同一个问题**（取回 1788 vs 窗口 359，上下文 + prompt cache 赢）。
那类场景不该用它 —— 近的用上下文，远 / 跨会话的才用它。

主体性那三行要连起来读：**次序会变（连续性）、变了能回滚（独立度）、但集合不变（不是裁判）**。
缺任一条都不成立 —— 只有连续性没有独立度，可能是模型随机性；有独立度但集合会变，就是推荐器。

**缓冲命中率**（`orient` 的 `cache` 一栏，从日志算 —— 不是估的）：

| 工作负载 | 命中率 |
|---|---|
| 同一问连问 5 次 | **80%** |
| 每问都不同（探索型） | **0%** |
| 真实轨迹（8 新 + 4 回头） | **33%** |
| 语料变了之后重问 | **0%**（作废，不是 bug） |

⚠️ 它是**复用率，不是智能指标** —— 命中率完全取决于**问题重复率**。
报一个不带工作负载的「命中率」是剧场，所以四个一起报。
另两个口径在 `sessions` 里：**缓冲曝光命中率**（摆出的支里多少被钻过）与**漏检率**（挤掉的里多少又被需要）。

### 工作能力调用（**不是准确性**）

上面那些是读数与成本。**这一栏量的是另一件事：能不能靠它把一件工作推进下去。**
⚠️ 所以这里**不给分**，只给结论 —— 把调用面的数字当成绩单，等于把「能开工」说成「干得好」。

| 探针 | 结论（不是分数） |
|---|---|
| `agent_task.py` | 一件真工作（60 个包的真 PyPI 元数据）**只靠 8 件工具的返回做完**：认结构 → 撞失配 → 造维度 → 再查 → 写回 → 报回执。**10 个决策点，每一个的依据都是某个返回字段，空依据 0 条** |
| `abstention.py` | 弃答分三层：**L1 维度不存在 / L2 取值不存在 —— 它挡得住**；**L3「项在有内容无」挡不住**（项都在，正文都没有）。⇒ 「返回了项」≠「答得出」。**但它给了 agent 一条正式出口**（`remember_answer(unknown=true, why=…)`）：弃答记成 `type=未答`，可查、可纠正 |

⇒ 这两条合起来说明的分工：**ldv 给结构事实，判断归 agent**。
它不替 agent 判断「正文里有没有那个信息」，但**会如实告诉 agent「有哪些键」「哪一支切不开」「你改了哪几处」**。

## 八件工具

| 工具 | 一句话 |
|---|---|
| `orient` | 我记得什么、透镜冻在哪、最近做过什么。**`changes` = 本会话改了哪几处**（新写 / 造维度 / 编译答案 / 降权支），只收写、按会话归属 |
| `ask` | 把问题翻成键，在树上查一支；默认只给正文 + 句柄。用到派生维度时给 `derived_provenance`（`derived_from`：写「原材料」的可当材料，写「模型推断」的只能当线索） |
| `drill` | 这一条有用（写进私人档案；agent 代钻与人同权） |
| `remember` | 往**自己的**语料写一条（只追加不覆写）。**写什么都直接进、直接能用 —— 使用不看来源。** 两条限制只跟标注有关：`filled_by` 只能记成你自己的 actor（不能替别人声明来源）；`evidence_status=已验证` 是**人的档** |
| `derive` | 造一个材料里没有的维度（带理由与来源，删 sidecar 即回退） |
| `remember_answer` | 把这次回答编进树，同时留一条 `我=是` 的记录。**答不出就用 `unknown=true` + `why`** —— 弃答也是一条结论（`type=未答`，可查、可纠正），不是沉默 |
| `undo` | 删掉这一项会怎样（**只算不改**，材料一个字节没动） |
| `next` | 结构哪里不平（必须 / 可延后 / 可忽略） |

细节与边界：[`docs/现在能做什么.md`](docs/现在能做什么.md)。

## 它不做什么

| 不做 | 为什么 |
|---|---|
| **不生成内容** | 只组织材料。要生成，那已经有 LLM 了 |
| **不打分 / 不排序** | 一旦有分数，它就是推荐器。支序会变（那是「视角」），但集合不变（那是「裁判权」） |
| **不做语义推理** | 不做蕴含、判不了「这两句话矛盾」。它做的是**结构诊断-修复**：需求失配 → 改结构 → 自洽 |
| **不让 agent 判错** | `verdict=wrong` 只接受 `actor=human` —— agent 可以提议，不能判错 |
| **不把规则交给 agent** | 怎么切分是系统内部实现。接口暴露「能做什么」，不暴露「怎么做的」 |
| **不判断「正文里有没有这个信息」** | 它只说「有哪些键」「哪一支切不开」。**「这一项里有没有你要的那个东西」要读正文才知道，那是 agent 的活**（`probes/abstention.py` 把这条量成了三层：前两层它挡得住，第三层挡不住）。⚠️ 所以「它返回了项」**不等于**「它答得出」 |

## 协议合规

用**官方 MCP Python SDK** 真连过（`probes/mcp_conformance.py`）：握手 / `tools/list` /
`tools/call` / 错误路径 / 连接存活，8 条全过。

两个实测踩到的坑（已修）：**协议版本必须协商**（写死旧版本会让新客户端直接断开，
现象是「握手时 Connection closed」而 server 没崩）；**不返回 `structuredContent`**
（没有 `outputSchema` 时返回它反而违规，`content[0].text` 里已经是完整 JSON）。
