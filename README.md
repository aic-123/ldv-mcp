# ldv-mcp

**把 ldv 内核包成一个 MCP 服务器** —— 你的语料装成一棵分层划分树，agent 通过七件工具在树上查、钻、推、记自己的历史。

**真人像平时一样用 agent，对这个插件零动作**：没有配置、没有选预设、没有「先建库再说」。
它只提供两样东西 —— **对 agent 的主体性**（私人语料 + 使用记录 + 自己的记忆），
和**一棵私人方向树**。

内核：[`aic-123/ldv`](https://github.com/aic-123/ldv)，**钉在 v0.1.38**（见 `core/PINNED`）。本仓库不改内核，只包它。

---

## 三十秒起跑

1. **装**：把上面的配置加进你的 MCP 客户端（`LDV_MCP_STORE` 指向一个空目录即可）
2. **指一个语料**（可选）：把你的 md 语料放进 `store/_data/<名字>/nodes/`；不指就用内置 36 项
3. **像平时一样问你的 agent** —— 它会自己 `orient`（我记得）→ `ask`（翻译 + 查）→ `drill`（有用）→ `remember`（记下来）；
   需要时它会 `derive`（造维度）、`undo`（删了会怎样）、`next`（该干什么）

```jsonc
// MCP 客户端配置（stdio）
{
  "mcpServers": {
    "ldv": {
      "command": "python",
      "args": ["/路径/到/ldv-mcp/server.py"],
      "env": { "LDV_MCP_STORE": "/路径/到/ldv-mcp/store" }
    }
  }
}
```

零第三方依赖（内核标准库自足，服务器手写 JSON-RPC）。

## 七件工具（四件动作 + 三件能力）

| 工具 | 类别 | 干什么 |
|---|---|---|
| `orient` | 动作 | 「我记得」—— 私人语料 / 透镜（理由+指纹+是否过期）/ 使用记录 / 最近动作 / **词汇表与取值分布**；**不给 ldv 名 ⇒ 列出所有 ldv** |
| `ask` | 动作 | 翻译后的查询。内部依次：键校验 → 透镜（没有就带 `lens` **自动冻结**）→ 支序原样 → 出处摘要；**默认只交正文 + 句柄**（id 与结构留在本地，agent 用不上）；`structure=true` 才给分支与谓词；带 `session` 记一条会话曝光 |
| `remember` | 动作 | 往自己的私人语料写一个节点（只追加不覆写，`filled_by` 照记） |
| `drill` | 动作 | 下钻 = 有用。**说「第 n 条」即可**（`n`），不必给方向 id；agent 代钻与人的同权 |
| `derive` | 能力 | **派生维度** —— 词汇表里没有的轴，agent 自己建（带理由与「从哪来」；删 sidecar 即逐字回退） |
| `undo` | 能力 | **反事实** —— 删掉一个项看什么会变，然后原样恢复。预测用**内核的 `impact`**（会变空 / 会缩 / 不在结构里），并与**实测**对照；指纹逐字比对过才报恢复成功 |
| `next` | 能力 | **反思** —— 后果三档（必须/可延后/可忽略），不是分数 |

原先的 `vocabulary` / `propose_spec` / `freeze_spec` / `spec_status` / `usage_status`
沉成内部机制：**透镜首次使用即自动冻结**，词汇表与使用记录并进 `orient`。
判据一条没少，只是不再占工具面。

**打包成插件只舍弃自由度，不牺牲能力** —— 哪件暴露、哪件故意不给、哪件是风险，
逐条记在 [`docs/能力对账.md`](docs/能力对账.md)。

## 这个插件凭什么被信

市面上「把库包进 agent」一抓一把。区别只在一个：**这个插件带着判据发货**——约束是机制，不是 prompt。

| 承诺 | 靠什么守 |
|---|---|
| 查询只用词汇表里有的键 | `checks/validate.py` ①：未知键当场拒，不猜最近的 |
| 不重排、不推荐 | ② 支序原样中转；重排可判（对一遍结构化结果就知道） |
| 方向函数只有这三个 | ③ 插件白名单；要加新的，先在内核里过它的判据 |
| 声明可复现、有来历 | `spec_store`：首次使用即冻结 + 理由原文 + 语料指纹，语料变则作废 |
| 每次回答能重放 | 查询结果带 `query`（查询式）与 `spec`（声明指纹） |
| 使用记录只改次序、不改答案 | 内核的两段通道原样：查询进缓冲，下钻才 promote |
| **两个会话指向同一 store 不会互相踩** | `checks/lock.py`：写锁（拿不到 ⇒ `StoreBusy`，不静默）+ 原子创建 + 同名维度不许静默覆盖；被杀进程的陈旧锁 120 秒后接管并记账 |

`python smoke_test.py` 二十八条判据（S1–S28）真起一个 MCP 会话跑完七件工具，含「未知键必须被拒」「工具面就是这七件」「支序必须与内核逐字相同」「remember 同 id 不覆写且之后透镜报 stale」「derive 删 sidecar 即逐字回退」「undo 恢复后答案与指纹逐字相同」「with_body 读到的正文与文件逐字相同且截断必报」。

## 两条放开的边界，和一条没放的

本产品相对内核**放开了两条**，都在文档里写死，不混：

1. **声明权给 agent**（内核的规矩是「什么算一个划分单元只能人声明」）。代价是声明变随机，补法是**首次使用即冻结**：agent 生成后落成文件，之后只读文件。复现性回到文件层。
2. **模型可以填内容**，但每一块都带出处（`filled_by`），且与用户写的、外部验证过的**三类分开可筛**。「已验证」仍然只能外部授予 —— 这条没放。

**没放的**：不作分、不排序、不推荐。支序原样中转；agent 重排即违规，且可判。

## 目录

```
ldv-mcp/
  server.py          MCP stdio 服务器（薄适配）
  smoke_test.py      二十八条冒烟判据（S1–S28）
  probes/            可复跑的实验（有/无插件差距、主体性判据）+ out/ 逐字留档
  checks/            发货自带的判据（键 / 白名单 / 支序）
  spec_store/        声明仓库（冻结 + 指纹 + 账本）
  presets/           三个开箱方向函数（人话 + 什么时候选哪个）
  core/              钉住的内核 v0.1.38（含它自己的全套判据）
  store/             运行时产物（语料 / 使用记录 / 声明）—— 不进 git
```

`store/_data/<名字>/nodes/` 放语料、`store/_data/<名字>/usage/` 是使用记录、`store/specs/<名字>/` 是声明。
（这个 `_data` 形状是内核的 usage 守卫要求的 —— 它只在 `_data` 下写使用记录，防的是「把运行时产物写进仓库」；产品把自己的 store 做成那个形状，就不用改内核。）

## agent 是第三方隐形使用者

用户 2026-10-24 定的形态：**插件对真人是透明的，agent 做双方的翻译官**。落成四条，每条都有机制兜着：

| 决定 | 机制 |
|---|---|
| **agent 的下钻算「有用」** | 与人的下钻同权 promote。代价是倾向会带上 agent 的翻译口味 ⇒ 兜底不是「不算」，是**可分解**：`orient` 报 `actor_split`（多少条记录来自 agent 声明的下钻） |
| **隐形只在对话里，不在日志里** | 每次工具调用落一行 `store/log/mcp-calls.jsonl`（时间 / 工具 / 参数 / 结果摘要），只追加。人随时能查「你替我过了哪些招、用了哪些键」，并能接管翻译层 |
| **答案的混合物必须报出来** | agent 被允许起草内容 ⇒ 每次 `ask` 带 `provenance`：`{语料: n, agent 填: n, 已验证: n}`，三类分开可筛。不藏混合物 |
| **actor 是声明，不是证明** | MCP 调用方自称 `actor`（默认 `agent`），服务器照记不验 —— 同 `filled_by` 的纪律 |
| **agent 与人是等价消费者** | 系统对两者的接口**完全一样**（都能查、能钻、能补缺口），区别只在记录里的 `actor`。agent 填的内容在 `provenance` 里**单独一桶**（判据 S26）——填了并说清就是合法补缺，填了不说才是问题 |

⚠️ 隐形的代价说清楚：它把首值时间压到最低，但让真人学不到词汇。解法是**翻译层可接管**（日志随时可查、可自己直接问），不是取消翻译。

## 三个缺口都由 agent 补，人只复核

**agent 与真人是等价消费者**：系统对两者的接口完全一样，区别只在记录里那一个 `actor` 字段。
所以撞到缺口时不是「判断该不该找人」——**三种缺口 agent 都能补，补完标记就行**。

| 缺口 | agent 怎么做 | 标记 |
|---|---|---|
| **词汇缺口**（问的维度不存在） | 映射到已有键；映射不上就建一个维度（`derive`，带理由与来源） | `_meta.derived_from` + `generated_by` |
| **结构缺口**（树在该细处不细） | 下次 `ask` 带新 `lens`（带理由）—— 自动冻成新的，旧的进 `HISTORY.md` | 透镜的 `generated_by` + `rationale` |
| **内容缺口**（材料里缺节点） | `remember` 写进私人语料（只追加不覆写） | `filled_by` |

⚠️ 这里曾经写过一张「升级判据（后果三档）」的表 —— 那是**旧立场**（人必须是关卡）的遗留，
与后来定的三件事（声明权给 agent / 模型代填放行 / agent 下钻算有用）冲突，已删。

**人不是关卡，是复核者**：能看（`provenance` 里 agent 填的有单独一桶）、能回滚
（删 sidecar / 删记录）、能接管（自己直接问）。**唯一的硬要求是标记如实** ——
填了却不说，那才是问题；填了并说清，那就是合法的补缺。

## 它不是什么

- **不是推荐器** —— 不排序、不打分、不主动说「你可能需要看这个」
- **不是语义理解层** —— 「A 意味着 B」这类推断它不做；它做的是结构：包含、可达、路径、反事实
- **不是已审核过的安全边界** —— 内核的存档格式仍是可信输入假设；别把陌生存档喂给它
- **不是一个产品化的服务** —— 这是研究内核的分发外壳，接口与保证以内核文档为准
