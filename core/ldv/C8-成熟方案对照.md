## §2 逐条对照

### N1 · 「不建这一层」有没有**不付代价**的做法

**成熟工程方案：ART（自适应基数树）的两项技术，名字就叫这两个。**

    Lazy Expansion      「inner nodes are only created if they are required to
                        distinguish at least two leaf nodes.」
                        —— **这正是 §K2 的「不建这一层」**

    Path Compression    「removes all inner nodes that have only a single child.
                        … Of course, this partial key cannot simply be ignored.」
                        —— **这正是「代价不会消失」**

⇒ **ART 的答案是第三条路：不建那一层，但把「用来区分的那一段」压进父节点。**

它明确说这个 partial key「不能就这么丢掉」，然后给了两种存法（悲观 / 乐观）：
悲观法把「所有被删掉的单子节点链上的键」拼成一个变长前缀向量存在父节点里。

**翻译成工程需要**（★ 这条改设计）：

我们现在的 §K2 只有两个选项：

    (a) 建了再作废      ⇒ 污染度量（已废弃）
    (b) 不建，项留在叶里 ⇒ **代价落在叶容量**（当前实现）

ART 给出 **(c)：不建，但把「区分的键」并进父方向的 payload**。
⇒ 分辨率**不丢**，代价从「叶容量」变成「父方向的 payload 变大一点」。

⚠️ 但这**不是无条件的**：它要求「区分信息」能**紧凑地表示成一个 payload**。
在我们的三个方向里：

    方向 A 键集      区分信息 = 一个键       ⇒ ✅ 能（payload 就是一个键集）
    方向 C 序列前缀   区分信息 = 一个符号     ⇒ ✅ 能（payload 就是前缀）
    方向 B 锚点可达   区分信息 = 图距离？     ⇒ ⚠️ **未必**，需要看插件能否给出紧凑的「区分见证」

⇒ **可执行的动作**：把 (c) 写成 `§I4` 的**可选返回值**（`劈开` 可以返回「一个方向 + 一段前缀」），
   然后拿三个方向实测：哪几个的叶容量真的降下来。**能降的降，降不了的留 (b)。**

> ### ✅ 实测结果（`C9` §1）：**一个都不能**，而且原因是**可证的**
>
> 上面那张表是**推测**，实测把它推翻了 —— 不是「能不能紧凑表示」的问题，
> 是**判空点上根本没有区分信息**：
>
>     方向      判空点数   其中「域内有差异（可搬）」   最大等价类   最大叶容量
>     ──────────────────────────────────────────────────────────────
>     keyset       7                0               10          10
>     sequence     8                0               10          10
>     reach        0                —                1           1
>
> `keyset` 的 7 个判空点，成员**键集完全相同**；`sequence` 的 8 个，**序列完全相同**。
> ⇒ 不是 payload 表示不了，是**没有东西可表示**。
>
> ⇒ **「代价必须落到叶容量」不是前提，是定理**：叶容量 = 最大等价类 =
>    该方向的**分辨率下界**，任何 payload 设计都越不过去。
> ⇒ 而且 (c) 在 A / C 上**已经实现了**（`common` / `p_star` 就是沿树吸收的那一段）。
>
> **这条发现的价值因此从「改设计」变成「换来一条检查」**：判「叶 = 不可分等价类」
> 的 `B17`（`ldv/checks/equivalence.py`），它顺带钉住了 `§K2` 的**第二半**（见下）。

> 出处：`art13` p.4–5（已核，逐字见 §4）。术语对应：
> `Lazy Expansion` ↔ §K2 + 叶不是终态；`Path Compression` ↔ §K2 的代价守恒。

**⚠️ 但有一个直接反例：SP-GiST 在同样的情况下选了「建 + 标记」。**

PostgreSQL 的 SP-GiST 遇到「劈不开」时，核心代码的做法与我们**相反**：

    「Therefore, if the picksplit function ends up placing all the leaf tuples in the
      same node, the core SP-GiST code will override that decision and generate an
      inner tuple in which the leaf tuples are assigned at random to several
      identically-labeled nodes. Such a tuple is marked allTheSame to signify that
      this has happened.」

⇒ 它**不**判「这一层不建」，而是**强制建一个退化的层**（多个同标签节点、随机分桶），并打上标记。

**为什么它敢这么选**：因为它有一个**物理约束** ——

    「otherwise it is not possible to split the leaf tuples across multiple pages,
      which is the ultimate purpose of this operation」

页装不下了，**必须**分。「不建」在那里不是一个可选项。

⇒ **对我们的意义**：这说明「不建」**不是** §K2 的唯一解，它取决于**约束**。
   我们的约束是「分辨率」，不是「页容量」。
   ⇒ 所以三个选项要按**约束**选，不是按「哪个更贴字面」选：

       约束是「必须装下」      ⇒ (d) 建 + 标记（SP-GiST 的 allTheSame）
       约束是「不丢分辨率」    ⇒ (c) 不建 + 父吸收（ART 的 path compression）
       约束是「层的语义要干净」 ⇒ (b) 不建，项留叶里（我们当前）

⚠️ **一条附带发现**：SP-GiST 的 `allTheSame` 恰恰**就是**我们前一版（a）想表达的东西 ——
   「建了一个表达不出新东西的层」。它**有一个正式的名字和标记**，
   而我们的做法是把它**写进账本当失效事件**。两者都承认这个层存在过，但 SP-GiST 让它**参与检索**，
   我们让它**不参与**。⇒ 这一点值得在设计文档里写清：我们**刻意**选择了「让它不参与」。

**★ 附带发现二：惰性展开必须配一条「进步量」守卫。**

SP-GiST 的 `longValuesOK` 模式是**逐级吸收前缀、直到装得下**。它给这条无界过程配了守卫：

    「To prevent bugs in operator classes from causing infinite insertion loops,
      the SP-GiST core will raise an error if the leaf datum does not become any
      smaller within ten cycles of choose method calls」

⇒ **两条可搬运的工程要求**：

    ① 终止判据是**物理预算**（装得下一页），不是语义上的「够细了」
       ⇒ 直接回答我们的「层数策略」留白：**不设全局深度上限，设一个进步量的守卫**
          （我们现在的进步量可以是「叶容量」或「payload 的细化程度」）

    ② 「十次没有进步就报错」—— 这正是我们的**「空转不许与通过长得一样」**，
       在别人的生产系统里的形态。而且它防的是**插件**（opclass）的 bug，不是内核的 ——
       ⇒ 我们的 `§K2 判空` 现在只判「一次分不开」，**没有防「反复声称能分却分不出东西」**。
          这是一条我们现在**没有**的检查。

### N2 · 否定结论必须带「它是对哪一批判的」

**成熟工程方案：Bazel 的 action cache key / rust-analyzer 的 Salsa 查询键。**

工程上的通行做法只有一句：**把输入集做成键的一部分**。

    cache_key = hash(输入集)
    ⇒ 输入集变了，键就变了，旧结论**自动**不再命中

这比「记住上次的输入集再比对」更硬：它不是「我记得我判过什么」，
是「这个结论**只对**这个键有效」。

**学术结果：Acar / Blelloch / Harper 的 `trace` + 变更传播。**

    「the change propagation algorithm interprets a trace to determine the correct
      order in which to propagate changes, and to determine which expressions need
      to be re-executed」

`trace` 里记的是**读写依赖**（谁读了谁）；输入变了，从被改的那个 modifiable
出发，沿 trace 把失效的边排进优先队列，逐条重算。

**翻译成工程需要**：

我们现在的 `_tried[did] = frozenset(成员集)` 已经是「结论带输入集」的雏形，但它是**比对的**，
不是**键控的**。两处可以收紧：

1. 把 `_tried` 的键从 `did` 改成 `(did, 成员集指纹)` —— 语义上等价，但**结构上不可能忘记比对**。
2. 现在只在**插入路径上**重判；Acar 的做法是**沿依赖边传播**。
   我们的「依赖边」就是见证（`§K1`）—— 一个方向的结论依赖它的成员，
   成员变了就失效。这条现在靠 `insert()` 的路径覆盖，**不是靠依赖图**。

⇒ **可执行的动作**：把「结论失效」写成**依赖驱动**（成员集变 ⇒ 该方向及其子方向的结论失效），
   而不是靠「插入路径恰好覆盖到」。前者可验证，后者要靠人相信。

> 出处：`acar02` p.1, p.7（已核，逐字见 §4）。

### N3 · 「增量」与「顺序无关」是不是只能二选一

**结论：不是。成熟方案里两者兼得，而且不贵。**

**学术结果一（正面）：Godin / Missaoui / Alaoui 1995 —— 增量概念格。**

正文原话（p.2）：

    「although the algorithm is incremental, the resulting hierarchy does not depend
      on any tunable parameters, algorithm specifics, or **the order in which the
      instances are acquired**」

⇒ 一个 **1995 年**的增量算法，**既增量又顺序无关**。所以「历史相关性是固有的」这句话，
   对**路径局部增量**成立，对**规范结构**不成立。

**为什么它能做到**：概念格是**关系的一个规范函数** —— 节点集由数据决定，不由历史决定。
增量算法只是**走到**那个格的另一条路，格本身不变。

**学术结果二（代价）：Naor & Teague 2001 —— 历史无关数据结构。**

    「data structures that are history independent, i.e. it is impossible to deduce
      from the memory representation of the data structure any information not
      revealed by its current state」
    —— 并注明这个问题**最早由 Micciancio 显式考虑**，他给了一个 **2-3 树的变体**。

关键手法：**在随机（或固定）的规模阈值上整体重建**。Naor–Teague 用秘密随机阈值
（防的是对手），我们的场景没有对手，用**确定的规模阈值**就够：

    |S| 跨过阈值 ⇒ 重建一次
    ⇒ 结构 = 当前集合的函数（＋阈值策略）⇒ 顺序无关
    ⇒ 摊还代价 O(1)（原文 Lemma 18/19 给的就是这个量级）

**翻译成工程需要**（★ 这条给了一个明确的、可实现的选项）：

    (i)   保持现状：路径局部增量 ⇒ 顺序相关，但**尺度不变**（已实测）
    (ii)  加「规模阈值重建」：|items| 每翻一倍就整体重建一次
          ⇒ 结构成为**集合的函数** ⇒ 顺序无关，且 `B15` 可以推广到「分批」
    (iii) 把节点集做成规范不动点（Godin 那条路）—— 代价最高，但最干净

⇒ **可执行的动作**：实现 (ii)（很小：`build()` 重跑一遍 + 一个阈值判断），
   然后**实测**：重建后的结构与「一次建完」是否同构。
   若同构 ⇒ 「历史相关性」这个说法要从文档里删掉，它不是固有性质，是**我们没做重建**。

> 出处：`godin95` p.2；`naor01` p.1（已核，逐字见 §4）。
> ⚠️ 注意「历史无关」在 Naor–Teague 那里是**隐私**动机；我们的动机是**可复现性**。
> 手法可借用，**动机不同，别把它的安全结论搬过来**。

**✅ 实测结果（`ldv/checks/rebuild.py`，36 项语料，扫 k ∈ {2,6,12,18,24,30,34,35}）**

三种做法都量了。(i) 是现状（第 1 步已量：三个方向**没有一个**同构）。

    方向       做法         同构全量的 k   k 指纹数   重建次数  重建工作量
    ─────────────────────────────────────────────────────────────────────
    keyset     (iii) 规范不动点  8 / 8         1        35       665
    keyset     (ii)  阈值重建    1 / 8         3         5        62
    reach      (iii) 规范不动点  8 / 8         1        35       665
    reach      (ii)  阈值重建    0 / 8         4         5        62
    sequence   (iii) 规范不动点  8 / 8         1        35       665
    sequence   (ii)  阈值重建    1 / 8         3         5        62

**⇒ 结果与 N3 的推测**部分**一致，但 (ii) 不成立**：

    ① (iii) 确实**买到了** —— 8/8 同构，且 **k 指纹只有 1 种**
       ⇒ 不只是「与全量一致」，而是「各 k 之间也一致」⇒ 结果不依赖初始批次
    ② 代价 **O(n) 每次插入**（35 次重建 / 工作量 665 = `2+3+…+36`）
    ③ (ii) **买不到**：1/8（A、C）、**0/8**（B）。差异发生在**两次重建之间** ——
       阈值之后添的项仍是增量的。⇒ Naor–Teague 买到的是「**摊还 O(1) 的重建**」，
       **不是**「结构 = 项集的函数」。这一条 N3 的推测**低估了**：
       「|S| 跨过阈值 ⇒ 重建一次 ⇒ 结构 = 当前集合的函数」只在**重建那一刻**成立。
    ④ `B8` **红** —— 规范重建每次全量重算，正是 §K3 要挡的形态

**⇒ 结论：不做。** 不是「太贵」，是**交换的东西不对等**：

    它要拿  §K3（**接口级**不变量：改一点不许全量重算）
    去换    「结构可复现」（**实现**性质）

第 1 步已说明「不同构」**不破坏任何一条检查** —— 它是**读数**，不是违规。

★ **顺带定下一条可以搬走的判据**：Acar 和 Godin 都把「增量 = 全量」当**正确性标准**在证，
而这里它只是读数。差别不在工程习惯，在**输出唯不唯一**：

    输出**唯一**（一个值 / 一个格 / 一个规范形）⇒ 是**正确性**要求
    输出**不唯一**（一族都合法的结构）      ⇒ 只是**实现性质**
                                              （本设计：§K1–§K9 是一族合法树）

⇒ 搬这条到新领域之前先问「**这个输出是唯一的吗**」。见设计文档 §10.1。

⚠️ 另报一个**与 id 无关**的读数（否则 `B8` 红只是比对的产物）：
   失效范围比 = 成员集合的对称差 / 方向数 —— 基线 **0.00** / 规范重建 **0.06**（A、C）、**0.29**（B）。
   ⇒ 规范结构对插入**近似稳定**：重建在**结果**上安全，代价**全在重算**上。
     §K3 挡的是**工作量**，不是**结果差异**。

### N4 · 增量维护的结果该不该等于从零重建

**学术结果：Acar 2002 的**正确性定理**就是这一条。**

    「prove that it is correct, that is, the adapted output is the same as the
      output of a complete re-evaluation with the changed inputs」

Godin 那篇也是同一个形状：他把增量算法的结果与**三个 batch 算法**对比
（「Results of empirical tests are given in order to compare the performance of the
incremental algorithms to three other batch algorithms」）。

**翻译成工程需要**（★ 这条可以立刻变成一条检查）：

    不变量：增量维护后的结构  ≡  从零重建同一集合的结构

⚠️ 但**我们实测它不成立**（`C7` §3.1.3：尺度相同、指纹不同）。
所以这条不能直接当判据 —— 要么

    (i)  接受它不成立，把判据降级成「尺度相同」（现状）；**但要在文档里写明这是选择，不是定理**
    (ii) 按 N3 的方案让它成立（阈值重建 / 规范不动点），然后**这条检查就能进退出码**

**「增量 ≠ 全量」是个真问题，不是风格问题** —— 两篇独立文献都把「等于全量」当作
正确性标准在证。我们现在既没有这条检查，也没在文档里承认它不成立。

⇒ **可执行的动作**：现在就加一条**只报不判**的检查（`增量结构 vs 重建结构 是否同构`），
   进输出不进退出码。它是 (i)/(ii) 的**决策依据**：哪几个方向同构、哪几个不同构。

> 出处：`acar02` p.1；`godin95` p.1（已核，逐字见 §4）。

**✅ 实测结果**：两条都做了。

    (i)  只报不判的读数 → `ldv/checks/divergence.py`（第 4 个度量，自带比较器自检）
         读数：三个方向**没有一个**能在后添 ≥2 项时同构；且差异**不在尺度**
    (ii) 让它成立的做法 → `ldv/checks/rebuild.py`（第 5 个度量）
         读数：**规范不动点 8/8 同构**（买得到），代价 O(n) 每次插入 ⇒ **不做**

⇒ 所以本设计最终取的是 **(i) 的加强版**：承认它不成立，但**在文档里写明这是选择，不是定理**
（设计文档 §7.1 / §7.3）。取 (i) 而不取 (ii) 的理由见 N3 的 ★：本设计的输出是
**一族合法树**，不是唯一那棵 ⇒ 「增量 = 全量」在这里**只是实现性质**。

### N5 · 扇出到底是几个 —— 成熟系统里的答案

**成熟工程方案一：PostgreSQL SP-GiST（空间划分 GiST）。**

    「Set nNodes to indicate the number of nodes that the new inner tuple will contain」
    「Each inner tuple contains a set of one or more nodes」
    「Some tree algorithms use a fixed set of nodes for each inner tuple;
      for example, in a quad-tree there are always exactly four nodes」

⇒ **`nNodes` 由 opclass 自己定**，不是固定两个。而且 `choose` 还能返回
   `spgAddNode`（「add a node to the inner tuple」）—— 扇出**可以长大**。

⚠️ **这条直接命中 `§I4` 的留白**：我们说「`§I4` 的『两个』是 B-tree 的遗产」，
   生产系统里的答案不是「要不要改」，而是**它本来就该由插件定**。

**成熟工程方案二：ART 的 adaptive nodes（`Node4` / `Node16` / `Node48` / `Node256`）。**

    「adaptive nodes do not affect the structure (i.e., height) of the tree,
      only the sizes of the nodes」
    「In order to efficiently support incremental updates, it is too expensive to
      resize nodes after each update. Therefore, we use a small number of node
      types, each with a different fanout.」

⇒ **扇出变化只改「空间」，不改「高度」。** 这一条很重要：
   它说明 `§I4` 的「返回一组方向」**不是结构问题，是节点表示问题**。
   而且成熟做法不是「任意 k」，是**一把小梯子**（4/16/48/256），按占用选。

**翻译成工程需要**：

    `§I4` 的签名从 `→ 两个方向` 改成 `→ None | 一组方向（≥2 个）`
    ⇒ 但**不要**要求插件给「最优 k」：A / B 本来就该给 2 个，C 给 k 个。
    ⇒ 这条改动**不动内核的遍历**（扇出 k 只是 `children_of` 返回 k 个），
       动的是 `§I4` 的返回值与 `§I3` 的「选哪个孩子」（现在是 `min`，k 叉时仍成立）。

⚠️ 而且要按 `§9` 的判据自问：这算不算「押错」？
   按 SP-GiST 的存在，`§I4` 的「两个」**确实是**一个被生产系统否掉的写法 ——
   但它**没有新增方法**，只是**放宽返回值**，所以仍然不是押错，是**签名要改**。

**本设计实测（已做，`C10` §2）**：改动落地后单变量对照 ——

    方向              方向数  层数  最大扇出  叶max   假阳率   各层
    keyset             25    7      2     10   49.8%   1/2/4/6/4/4/4
    reach              71    7      2      1   22.4%   1/2/4/8/16/32/8
    sequence           16    5      7     10    0.0%   1/7/4/2/2
    sequence(二分)      21    7      2     10    0.0%   1/2/4/6/4/2/2

⇒ **C 省 5 个方向、2 层，分辨率（叶容量 10）与假阳率（0.0%）一个数没动**；
  **A / B 一个数没动**（反向判据）—— k 叉只动了它该动的地方。

⚠️ **但 ART 那条「扇出只改空间不改高度」在 C 上不成立**（7 层 → 5 层）。
   ART 的节点是**定长**的（同一批键、按占用选节点类型），而我们的 `劈开` 是
  **按需**的、**一次定形**的（§K2）—— 扇出大 ⇒ 一次就把符号分完 ⇒ **少一层**。
   ⇒ ART 的结论适用于「定长节点 + 上溢分裂」，不适用于「按需展开 + 一次定形」。

⚠️ **顺带买到的**：阈值重建（Naor–Teague）在 C 上从 1/8 变成 **8/8 同构、k 指纹 1 种**
   （见 §7 第 3 步）—— 扇出由插件定 ⇒ 首次重建时符号齐了就定形。
   对扇出恒为两个的 A / B 仍然买不到（1/8、0/8）。

> 出处：`postgres-spgist`（已核，逐字见 §4）；`art13` p.4（已核）。

### N6 · 那个不对称契约的成熟名字

**结论：它有名字，而且有一整套理论。**

**成熟工程方案：Bloom filter（1970）。** 「假阳允许、假阴禁止」是它的定义性契约。
同族：Cuckoo filter、quotient filter、Count-Min sketch —— 整个**单侧误差**数据结构领域。

**学术结果：McConnell / Mehlhorn / Näher / Schweitzer，*Certifying Algorithms*（2011）。**

    「A certifying algorithm is an algorithm that produces, with each output,
      a certificate or witness (easy-to-verify proof) that the particular output
      has not been compromised by a bug.」

它把强度分三档，其中**「证书型」**的定义（p.24）逐字是：

    ∀x,y,w (y = ⊥ ∧ W(x,y,w)) ⟹ ¬ϕ(x)
    ∀x,y,w (y ∈ Y ∧ W(x,y,w)) ⟹ ¬ϕ(x) ∨ ψ(x,y)

⇒ **我们的 `§K8` 就是一个 witness property，`B16` 就是它的 checkability。**

    我们说的                      他们的说法
    ────────────────────────────────────────────
    命中说「否」必须是真的          witness 必须蕴含 postcondition
    「否」要给出依据（覆盖）        witness w 必须可检查
    `B16`（members ⊆ 覆盖）         checkability（「trivial to determine W」）
    假阳允许                       输出 y 可以错，但**必须有 witness**（弱证书那档）

**翻译成工程需要**：

1. `§K8` 现在写的是「假阴禁止」。用他们的语言更准确：**`命中` 是「否」这个答案的检查器**，
   而「否」的**证书**是方向的 payload。⇒ 把 `§K8` 改写成「witness property + checkability」两条，
   和 `B16` 形成**配对**（这正是我们已经在做的，只是没有名字）。
2. 他们有一个**我们没有的**要求：「**Simplicity**: The implications (3) have a simple proof.」
   ⇒ 检查器必须**比被检查的东西简单**。`B16` 现在用的是「按 `§I3 代价` 重算归属」——
   它复用了内核的分配逻辑（`false-green` 形状 3「共享盲点」）。
   按他们的标准，这不是一个合格的 checker。**这是本轮找到的一条真缺陷。**
3. 对这条缺陷，他们还有一句**更硬的判词**（§12「Checkers」，p.77）：

       「a checker that wants to catch errors **immediately** must essentially
         implement a priority queue by himself.」

   ⇒ 判词的意思是：**想立即抓错，就只能自己再实现一遍**。所以 `B16` 只有两条路 ——
   要么独立重实现分配逻辑（贵），要么降级成「只报不判」的弱版本。**没有第三条便宜的路。**
4. 「假阴禁止」的理由也在这里，而且是**代价**而不是约定：若要求两侧见证都短，
   问题就只剩 NP∩coNP（§5.8 + Lemma 5，p.32）。⇒ 给不出见证的答案只能**禁止**。

> 出处：`mcconnell11` p.1, p.22–24, p.27, p.32, p.77（已核，逐字见 §4）。

### N7 · 插入引发的「部分结构重构」范围

**学术结果：Godin 1995 把更新**分解成四个方面**，而且给出重构的**精确范围**。**

    「The updating is decomposed into four aspects: the X set, the X' set,
      the parents and children.」
    「some old children may have to be removed if the new children fall in between
      the old child and the modified pair. ... the edge from that parent to the
      generator (e.g., edge(#3,#8) in Figure 2) is replaced by two edges」

⇒ 重构是**局部的**，而且范围**可判定**：只有「生成元（generator）与其父之间」的边会动。
   生成元的定义：**产生这个新交集的、最小的那个老节点**（`inf`，唯一性由格性质保证）。

    「This pair is the smallest (inf) old pair that produces the intersection.
      Unicity of the greatest lower bound is guaranteed by the lattice property of G.」

**翻译成工程需要**（这条正好回答最初那个问题）：

我们现在的 `§M3`（变动 ⊆ `Cone(x)`）是**断言局部性**，但没有说**重构该做多大**。
Godin 给的是**构造性**的：重构范围 = 「新方向的生成元 → 它原来的父」这条边。

⇒ 差别很实际：我们现在**只在插入路径上重判**（路径 = `Cone(x)`）。
   Godin 说还要看「新节点插进了谁和谁之间」—— 也就是**兄弟方向**。
   这可能正是 `C7` §3.1.3 里「不同构」的来源：**我们漏了兄弟侧的边重连**。

⚠️ 这是**假设**，不是结论 —— 要实测才知道。但它是**可证伪的**：
   按 Godin 的规则补上边重连，再看增量与重建是否同构。

> 出处：`godin95` p.6–8（已核，逐字见 §4）。

### N9 · 不可变 + 分叉的成熟形态

**学术结果：Driscoll / Sarnak / Sleator / Tarjan 1989, *Making Data Structures Persistent*。**

它给的正是 `§K4`（只分叉不覆盖）的技术名字与代价表：

    path copying    每次改动复制整条路径 ⇒ 简单，代价 O(log n) 空间
    node copying    每个节点留几个版本槽 ⇒ 摊还 O(1)，实现复杂
    fat node        节点里存全部历史      ⇒ 最通用，最贵

**翻译成工程需要**：我们现在的账本（`§K4`）是**最保守**的形态（全量追加），
   而方向结构本身**没有持久化**（`§10` 留白）。
   ⇒ 做持久化时，直接按 Driscoll 的三种策略选一个，**不要自己发明**。
   按我们「只分叉不覆盖」的强度，`path copying` 是起点。

⚠️ **未核**：本轮只见到二手描述，**没拿正文**。同上，先核再引。

### N10 · 怎么判断一个「方向」好不好用

**现状**：我们有 `假阳率`、`§K2 判空`、`叶容量` 四个度量，但**没有跨设计的可比口径**。

**成熟工程方案：ANN-Benchmarks（Aumüller / Bernhardsson / Faithfull）。**
它把索引质量统一成一条**曲线**：召回率 vs 每秒查询数（recall@k vs QPS），
然后所有结构在同一张图上比。

**翻译成工程需要**：

我们的「分辨率（叶容量）」与「层数/方向数」本来就是一对**权衡曲线**，
现在却是**两个孤立的数**。按 ANN-Benchmarks 的做法，应该报**曲线上的位置**：

    横轴  每个方向平均扫过的项数（≈ 查询代价）
    纵轴  分辨率（1 / 叶容量）或 覆盖率

⇒ 这样「C 花 21 个方向换叶容量 10」与「B 花 71 个方向换叶容量 1」才**可比** ——
   它们现在是同一条曲线上的两个点。

⚠️ **未核**：ANN-Benchmarks 本轮没拿正文。要引先核。
