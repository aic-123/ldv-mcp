## §0 闸门问题与答案

> **问：`§I4` 的签名改动，付了重新验证的代价之后，站得住吗？**

**答：站得住 —— 而且这一步挖出了一处真的缺陷。**

    改的签名          3 处（返回一组方向 / 「分不开」显式返回 / 带上父方向）
    推翻的接口条款     0 处
    新发现的**缺陷**    1 处（健全性在**维护路径**上不成立，三个方向都有）
      ├ 其中已修       1 个方向（A · `keyset`）
      └ 待裁定         2 个方向（B · `reach` / C · `sequence`）—— 见 §4 / §6

⚠️ **后续（本节是当时的快照）**：B · `reach` 走**出路 (1) 根记账**（已落地）；
C · `sequence` 走**出路 (4) 项留在父方向**（已落地）。设计文档 `§10.2 A′` 当初
还留了 `reach` 的出路 (3)，**2026-10-07 已裁定不采纳**（靶子按定义不存在）。

「站得住」指的是：三处改动**没有一处**需要新增方法、需要拆方法、或需要把某个
返回值换个类型。`§I4` 仍然是**一个**方法，仍然只返回「候选方向」或「分不开」。

**为什么必须付这个代价**：`§I4` 是七个位置里最像 B-tree 遗产的一个
（`C5b` §2.1 / §6）。它「能装下」三个差异极大的方向，但每次都要多花点东西。
装得下 ≠ 装得好 —— 所以「要不要改」和「改完还是不是同一个接口」是两件事，
后者只能靠**重新跑一遍全部检查**回答。

## §1 改了什么

### 1.1 返回值：`→ 两个方向` 改成 `→ None | 一组方向（≥2 个）`

    §I4 劈开(父方向, 一组项) → None | 一组方向（≥2 个）        ← PickSplit

三个位置，三件独立的事：

| 位置 | 原来 | 现在 | 为什么 |
|---|---|---|---|
| **分支数** | 硬编码 2 | 由插件定（k 叉） | 二分是 B-tree 遗产。有序方向（序列前缀）的自然形状是 **trie —— 一个节点按「下一个符号」分出 k 个** |
| **「分不开」** | 编码成「返回两个相同 payload」 | 显式返回 `None` | 见 1.2 |
| **少给（<2 个）** | 静默当成分不开 | **违约**（`PluginContractError`） | 内核不替插件猜 |

### 1.2 为什么「分不开」必须是插件**说**出来的

原编码（「两个相同 payload」）把判定**藏在内容里**，于是两种东西长得一样：

    插件**判**分不开        接口的正常用法 —— 插件的判断
    插件给的候选**切不动**   候选退化 —— 插件与内核之间的摩擦

⇒ 现在分开记（账本 `unsplittable` 的 `by` 字段 = `"plugin"` / `"kernel"`），
`stats()` 分两个数报。**分开记才有信息量**：一个永远返回空组的插件，
与一个诚实声明「分不开」的插件，在「从内容反推」的读法下产出**完全相同**的账本 ——
那就是「空转与通过长得一模一样」在接口层的形态。

实测（36 项语料，一次建完）：三个方向 `判空·切不动` **一律 0** ——
即插件确实在用自己的判断说话，内核没有替它兜底。

### 1.3 为什么带上父方向

`劈开` 只看得到项时，它必须从项里**重新猜**父的意图，而猜出来的东西
**不保证**是父的细化。带上父方向，子方向就能**继承**父的约束 ⇒ 包含关系
变成**结构上成立**的，而不是靠猜。

`C5b` §3.1 把这条记成 E1（A 的 8 处过滤器不嵌套），并指出
`§I4` 的签名还有第二种取法。现在取了。

## §2 改动一：k 叉（返回一组方向）

### 2.1 正向：C 真的省下了东西

单变量对照 —— 唯一变量是 `sequence.split` 的返回值个数（k 叉 vs 强制二分），
其余一字不动：

```
方向              方向数  层数  最大扇出  判空  叶max  叶avg   假阳率   各层
keyset             25    7      2     7    10   2.77   49.8%   1/2/4/6/4/4/4
reach              71    7      2     0     1   1.00   22.4%   1/2/4/8/16/32/8
sequence           16    5      7     8    10   3.27    0.0%   1/7/4/2/2
sequence(二分)      21    7      2     8    10   3.27    0.0%   1/2/4/6/4/2/2
```

    C：方向数 21 → 16（省 5），层数 7 → 5（省 2）
       叶容量 10 → 10（**不变**），假阳率 0.0% → 0.0%（**不变**）

⇒ **C 用更少的层与更少的方向，买到了一模一样的分辨率与一模一样（零）的假阳率。**
这是「零假阳的方向也能有结构」的第一个实例 —— 在此之前 C 只能靠二分硬凑。

### 2.2 反向判据：A / B **一个数都没动**

A（键集包含）与 B（锚点可达）是**真的二分** —— 它们的 payload 语义里
没有比「一个键有 / 没有」「按图上位置取中点」更细的 k 分解。所以：

    改 k 叉之后，A / B 的  方向数 · 层数 · 最大扇出 · 各层方向数 · 叶容量   一个数没动
    B 连假阳率也没动（22.4% → 22.4%）
    A 的假阳率后来动了（54.6% → 50.1%）—— 那是 §3 那处 `req` 修复造成的，**另一个变量**

⇒ 这条反向判据证明：k 叉只动了它该动的地方。
（A / B 的 `split` 恒返回 2 个 ⇒ 走的是同一条建子方向的路径，`_probe` 的
「每个候选一个 `slot`」也退化成原来那种「两个候选互不相同」。）

### 2.3 一个顺带买到的：阈值重建在 C 上成立了

```
方向        规范不动点（8/8 同构、k 指纹 1 种）   阈值重建（Naor–Teague）
keyset      8/8                                1/8 同构、k 指纹 3 种、最早同构 k=35
reach       8/8                                0/8 同构、k 指纹 3 种、最早同构 无
sequence    8/8                                8/8 同构、k 指纹 1 种、最早同构 k=2
```

C 的阈值重建**买到了**：扇出由插件定 ⇒ 首次重建时符号齐了就定形，
之后添的项只会落进**已有**的子方向。

⇒ §10 第 3 步「不做规范重建」的判定**不变，但理由收窄了一句**：
不是「阈值重建做不到」，是「**扇出恒为两个的方向**做不到」，
而 §K3（接口级不变量）比「结构可复现」（实现性质）更贵。

## §3 改动二：带上父方向（`forb` 继承）

单变量逐级对照 —— 每一级只差一处：

```
变体                              覆盖越界   已展开   判「是」   假阳   假阳率
① 不续 forb（带上父方向之前）            14     12     926    525   56.7%
② 续 forb，req 掺 common（改前）         0     12     793    392   49.4%
③ 续 forb，req 只续父（改后）              0     12     803    402   50.1%
```

⇒ §10 的预测「**假阳率大概率下降**」**成立**：56.7% → 49.4%（且判「是」的**绝对**条数
从 926 掉到 793 —— 不是「分母变大」造成的）。覆盖嵌套从 **14 次越界**掉到 **0 次**。

⚠️ ① 的 14 次越界不是「改前的缺陷」，是 `forb` 不续的**必然结果**：
父说「不含键 f」，子方向却把 `forb` 清空了 ⇒ 子方向重新收下含 f 的项。
那些项在父那里本来已经可以被否掉 ⇒ **纯假阳**（性能损失，且会累积，§K8）。

## §4 ★ 改动三挖出来的东西：健全性在**维护路径**上不成立

### 4.1 怎么挖出来的

改 `forb` 之后，注入验证的度量「增量 ≡ 全量」**基线就不一致**了：

    keyset 全量 25 个方向，先建 2 维护 34 → 23，先建 12 维护 24 → 21

隔离到单变量：不续 `forb` 时 25 全同，续 `forb` 时变。于是往下挖，
发现变的原因不是记账，是 `劈开` **自己切不动了**：

    `common` 与 `p_req` 一起把子方向的 `req` 抬得比父高
    ⇒ 某个项在两个子方向上**代价打平**（都是 1）
    ⇒ 平手判给靠前那个 ⇒ 一侧为空 ⇒ `§K2` 判「切不动」⇒ 这一层不建

**顺着这条线再往前一步，撞上了真东西。**

### 4.2 真东西：`members(d) ⊆ 覆盖(d)` 在维护路径上破了

§1 的硬要求表第三行（健全性，`B16` 守）在**两条路径上不是同一件事**：

    一次建完     每个方向的成员集在**第一次展开时就是完整的**
                 ⇒ 子方向的 payload 从这批成员算出来，一定盖得住它们 ⇒ 天然成立
    维护路径     成员是**后来才长起来的**，而 payload 在劈开时就**冻结**了
                 ⇒ 子方向收不住「它没见过的项」⇒ 破了也没人查

而 `B16` 只跑**一次建完**那条路。实测（36 项语料，改 `forb` 之后、修 `req` 之前）：

```
方向        一次建完        先建 2 维护 34        假阴（B1，同一批）
keyset      0 / 159        123 / 227            42 / 385
reach       0 / 224        313 / 385            44 / 384
sequence    0 / 122         68 / 210            25 / 154
```

⇒ **一次建完全绿、维护路径全红，而且真的产生假阴。**
这是「空转与通过长得一模一样」在**流程**上的形态：
检查存在、是绿的，但它从没跑在出问题的那条路上。

而且它**不是本次改动引入的** —— 不续 `forb` 的版本在维护路径上同样破
（先建 2：47/235 越界），只是破得少一点。

### 4.3 根因：`劈开` 不许用**当前成员**算子方向 payload

三个方向各有各的形态，但**是同一句话**：

    一个项**什么时候**落进 d，不由 d 决定 —— 由**下降**决定
    （`§I3 代价` 取最小；取不到 0 也照落，落点就是那个代价最小的子方向）
    ⇒ 只要 `覆盖(父) ⊄ ∪覆盖(子)`，就**一定**有项落进「它不满足」的方向
    ⇒ `members(d) ⊄ 覆盖(d)` ⇒ `命中` 的「否」就**证不住** ⇒ 假阴（§K8 禁）

```
方向     `劈开` 用了什么「当前成员」算出来的东西        形态
A       `common`（当前成员的键集之交）              子方向的 `req` 比父还高
B       「只按成员分」（payload = 成员自己）          子方向盖不住**父的 payload**
C       `p*` = 当前成员的最长公共前缀（压缩 trie）    子方向跳过了「父前缀到 p*」之间那段
```

### 4.4 A 已修：一行，单变量验证

```python
# 改前
req = p_req | common
return ((req | {best}, p_forb), (req, p_forb | {best}))
# 改后 —— 两个字段都**只从父续**
return ((p_req | {best}, p_forb), (p_req, p_forb | {best}))
```

`common` 仍然用来**挑判别键**（信息量最大的那个），但**不进 payload**。
这样 `覆盖(父) ⊆ 覆盖(子1) ∪ 覆盖(子2)` 是结构上成立的：
x 满足父 ⇒ 要么有 `best`（落子 1，代价 0），要么没有（落子 2，代价 0）。

```
变体                        维护路径越界（先建2）   维护 B1   方向数随 k
① 不续 forb                   47 / 235            否       25 全同
② 续 forb，req 掺 common      123 / 227           否       23/23/21/25/25
③ 续 forb，req 只续父（改后）    0 / 235            是       25 全同
```

⇒ 一行修好：维护路径 B1 / B16 转绿、覆盖越界 0、方向数恢复 k 不变。
代价：全量假阳率 49.4% → 50.1%（**判「是」803 次里多 10 次**）。
**这不是「性能换正确」的交易，是把一笔本来就兑现不了的声称收回来** ——
`common` 声称「落进来的东西都带这些键」，而劈开兑现不了它。

## §6 留白（本轮**没做**的，需要裁定）

### ★ 裁定请求 · 健全性在 B / C 的维护路径上仍然不成立（**已写进设计文档 §10.2**）

A 修完了。**B 与 C 没修** —— 不是没时间，是它们的修法**不是同一处**，
而且各自要一个裁定。当前它们以**度量**形式报出（`run_checks` 每次都会印），
**不是判据** —— 这一点必须说清理由：B / C 的修法未定，而一条基线就红的判据
**过不了注入验证**（注入验证要求基线绿）。裁定之后，这一条要升级成判据。

修好 A 之后三条的读数（维护路径，先建 6 维护 30）：

```
keyset      0 / 232      ✓
reach     246 / 328      ✗   最差方向 = **根**（D0）
sequence   36 / 176      ✗   最差方向 D4（payload 已终结的前缀）
```

**B · `reach` —— 根的外生 payload 盖不住后来添的项。**

    `覆盖(d) = reachable(payload(d))`，而 `payload(根)` 是**人声明的锚点集**。
    增量夹具里根 = 「当时已知的 k 项」⇒ 后来添的项走不到任何锚点 ⇒ 落在根覆盖外。
    实测：根 = 前 2 项时，根上 30/36 个成员越界；把根改成全集，根的越界降到 0，
    但**内部仍有 161 个** —— 因为子方向的 payload = 劈开时的成员，
    而它盖不住「父的 payload」（父的 payload 可能比成员多）。

    这是 `§K9`（外生 / 内生边界）的问题，三条出路：

        (1) `insert` 的项必须落在**根覆盖内**，否则记一条事件、**不塞进结构**
            ⇒ 承认「最外层意图之外」是一个合法状态，并给它记账
        (2) 根的 payload 随插入**加宽** —— 但方向是不可变的（§K4），要改这条
        (3) 子方向的 payload 从**父的 payload** 派生（与本轮修 A 同一个原则）
            ⇒ 代价：子方向覆盖 ⊇ 父方向覆盖，树在覆盖意义上不再变细

    ⚠️ 顺带一个必须一起定的问题：`reach` 的 `代价` 与 `覆盖` **不重合** ——
       `代价 = 0` 只对**锚点本身**成立，而 `覆盖 = reachable(payload)` 大得多。
       所以 `B16` 现在用的判据（`代价 = 0`）对 B **过强**。
       `reach` 的模块 docstring 声明的要守的只有 `归属 ⊆ 可达`（单向）。
       ⇒ 要么 `B16` 改成按**插件自己声明的覆盖**判（需要接口加一个「覆盖谓词」），
         要么 `reach.penalty` 改成 `0 ⟺ 可达`。

**C · `sequence` —— 前缀语言的「覆盖不漏」**不可能**用有限个子方向做到。**

    父的覆盖是 `{x : p ⊑ seq(x)}`，`p` 后面那个符号来自**无穷字母表**，
    而子方向只能枚举**当前成员**用到的符号
    ⇒ 一个带**新符号**的项，任何子方向都收不住（实测：一改就 `IndexError`，
      因为那个项根本不满足父的前缀）。

    三条出路：

        (1) 加一个 **catch-all 子方向**（payload = 父的前缀本身）
            ⇒ 覆盖不漏成立，代价是它永不细化、叶容量变大、`B17`（叶 = 等价类）可能破
        (2) 子方向枚举**整个世界**在该位置的字母表（插件知道全部 `seq`），
            空桶也建 ⇒ 需要内核允许空壳方向，`§K2`「不建这一层」与
            「不存在空壳方向」两条不变量要一起放宽
        (3) `insert` 遇到收不住的项就拒绝 / 记事件（同 B 的出路 1）

    ⚠️ 三条都**不是**「改一句代码」，都会动到已定的不变量 ⇒ 必须裁定。

### 其余（与上一轮相同，未变）

2. 曝光模型标定 —— 需要真实使用数据。
3. `common` 丢掉的那部分选择性要不要用别的办法找回来
   （例如让它进 `forb` 而不是 `req`）—— 属于**性能**，不是正确性，留白。
