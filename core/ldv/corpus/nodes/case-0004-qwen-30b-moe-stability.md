**情境特征**：要在**大规模 MoE** 上把 RL 跑稳，且推理用 FP8、训练用 BF16——
也就是**故意让推理精度低于训练**，把训推偏差拉到很大的压力测试条件下。
单梯度步约耗 **5~6 GPU 小时**，全程**数十万 GPU 小时**。

**考虑过的选项**：论文先把「为什么 token 级目标能代替序列级目标」拆成两个条件
（见 `con-0008`），再按这两个条件逐项检查现有稳定手段。

**理由**：既然不稳的根源是两个因子（训推偏差、策略陈旧度），
那就分别看每个手段**实际压住了哪一个**，而不是笼统地「多加几个稳定技巧」。

**结果——分成两张表**：

**on-policy 下**（每批 rollout 只更新一次）：

| 做法 | 结果 |
|---|---|
| 基础 policy gradient + 重要性采样校正（论文叫 MiniRL） | **性能与稳定性都最好** |
| 加 length normalization | 训练稳，但**目标有偏，性能次优** |
| 去掉训推重要性采样校正 | **迅速崩溃，熵急剧下降** |
| 上 R3（rollout routing replay） | on-policy 下**没有增益** |

**off-policy 下**（一批 rollout 切成多份做多次更新）：

- **clipping 与 Routing Replay 两者都变成必需**，缺一个就提前崩溃、峰值性能被压低
- off-policiness **小**时 R2 够用且更好；off-policiness **大**时**必须用 R3**

**一个反直觉的结论**：论文报告——**训练一旦稳下来，三种不同的冷启动初始化
（分别蒸馏自 Qwen3-Max-Thinking-Preview、DeepSeek-R1-0528、gpt-oss-120b）
最终性能可比**。作者据此主张把注意力放回 RL 本身，而不是过度纠结冷启动数据。

**反事实**：如果不做「按两个因子分项归因」而是笼统堆稳定技巧，
就得不到「on-policy 下 R3 无增益」这个结论——而它恰好和另一篇工作（Ma et al. 2025）**冲突**。
论文自己把这个冲突归因于对方规模小（≤180 步）且推理精度设置更宽松。

**这条案例能支持什么、不能支持什么**：

- 它支持「**在这个 MoE + FP8 推理的配置下**，稳定手段该按 on/off-policy 分开选」。
- 它**不**支持「R3 普遍无效」——那是**单一配置下的实测结果**，论文自己也没这么说。
- 冷启动那条结论**来自更小的模型**，不要当 30B 上的证据用。

**⚠️ 一条副作用必须记住**：Routing Replay 会**引入偏差**——它把路由专家固定住，
目标策略就不再是原来的策略了。论文表 1 指出 R2 在**第一个 mini-batch 上不改变目标策略**，
R3 则**在所有 mini-batch 上都改变**。论文自己的话是：很难断定它的利弊哪边更大。
