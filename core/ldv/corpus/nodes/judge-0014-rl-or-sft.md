**来源给的第一句是**：「**当有高质量专家数据时，SFT 通常被优先作为初始阶段**」——
注意它说的是**次序**，不是"哪个更好"。

变量：有没有高质量专家数据、奖励能不能可靠地训出来、策略模型对这个任务熟不熟

## §6 里能直接引的四条

1. **有高质量专家数据 → 优先 SFT 起步**（理由：实现更简单、更稳）。
2. **能训出可靠奖励模型 → 常见做法是「先 SFT 再 RL」，而且这通常达到报告里的最好成绩。**
3. **SFT 是必需的**，当**策略模型对下游任务不熟**、或者**没法高效采到足够的正样本**时。
   但代价是：**SFT 相比 RL 可能降低泛化能力**。
4. **直接上 RL** 能更好地平衡性能与探索能力，但它会遇到**熵坍缩**或**reward hacking** 这类问题
   ——综述把这一点列为"为什么大量算力仍然花在 SFT 上"的可能原因之一。

★ 综述还引了一篇标题就很直白的对比研究：**《SFT memorizes, RL generalizes》**（arXiv:2501.17161）。

## 怎么确认

1. 先问：**我手上有高质量专家数据吗**（不是"有数据"，是"专家级的"）
2. 再问：**我的奖励能不能可靠地算出来**——程序可判？还是要训奖励模型？
3. 再问：**基座对我这个任务熟不熟**（不熟 → SFT 那一条必做）
4. 三条都有答案之后，**次序**基本就定了：数据→SFT，奖励→RL，两者都有→先 SFT 再 RL

**第 2 步是分水岭**：奖励不可靠时，RL 那一段不只是"效果差"，是**会往错的方向优化**。
那一步的判断在 `con-0006`（规则奖励 vs 奖励模型），不在本节点重讲。

判据：如果**奖励必须靠训一个模型来给**，那你就同时背上了 reward hacking 的风险——这时"先 SFT 再 RL"这条常见做法里的 RL 阶段，前提要先满足。

## 一条边界

**本节点不给"该花多少算力""该用多少卡"。**
来源里没有这类内容，而本结构**不收**参数型/配置型内容——那种东西的正确位置是官方文档，
抄进来只会得到一个会过期的副本。
→ 同理，**本节点不给"RL 一定比 SFT 强"的结论**：
§6 的措辞是**互补**，并且明确列了 RL 自己的失效模式。
