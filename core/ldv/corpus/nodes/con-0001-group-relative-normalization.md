对同一个 prompt 采样 G 条完成，得到 G 个奖励。每条的优势 = **(自己这条的奖励 − 组内均值) ÷ 组内标准差**。

**论文的三处关键细节**（§4.1.1–§4.1.2）：

1. **同一个组内所有 token 共享同一个优势**。结果监督下，归一化奖励在整条输出的**末尾**给出，
   然后把这个值赋给该输出里的**每一个 token**。
2. **KL 项直接加在损失里，不是加在奖励里**。论文原话是这么做可以
   **避免把 Â 的计算复杂化**——PPO 是把 KL 惩罚塞进奖励的，GRPO 不这么做。
3. **为什么「组内相对」是合理的**：论文给的理由是——**奖励模型本身就是在
   「同一问题的多个输出之间做比较」的数据上训练的**，所以用组内比较来算优势，
   与奖励模型的**比较性质**对齐。

**要点**：基线不是学出来的，是**同一组内现算的**。所以 GRPO 不需要价值网络。

**代价在后面**：**优势的尺度取决于组内奖励的离散程度**。一组全对或全错时标准差趋近 0，
这一项会被放大到不稳定——这是后面几个节点的共同起点。
`exc-0001` 讨论的就是把这一项拿掉之后的取舍。

**过程监督变体**（§4.1.3）：如果奖励是分步给的，优势 = **从当前 token 起、后续各步归一化奖励之和**。
也就是说，同一个归一化机制在两种监督粒度下都成立，只是「归一化的对象」从整条输出变成了一步。
