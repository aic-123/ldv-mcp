**情境特征**：想证明"推理能力可以不靠人类示范获得"。当时的通行做法是
大量人工标注的推理轨迹 + SFT，成本高，且模型能力上不去。

**考虑过的选项**：论文选了最激进的一条——**不做 SFT**，也不提供人工推理轨迹，
只给可验证任务上的**规则奖励**，让 RL 自己去长。

**理由**：如果推理能力真的能从 RL 里涌现，那人工标注就不是必要条件。

**结果——Table 3 的 R1-Zero 列**：

| 基准 | R1-Zero |
|---|---|
| **AIME 2024**（pass@1） | **77.9**（训练起点 **15.6**） |
| AIME 2024（自洽性解码） | **86.7** |
| **MATH-500** | **95.9** |
| CNMO 2024 | 88.1 |
| **GPQA Diamond** | **75.8** |
| LiveCodeBench（pass@1-CoT） | 50.0 |
| Codeforces | **80.4** 百分位（rating 1444） |
| SWE Verified（Resolved） | 43.2 |

论文对自洽性那个数字的说法是：**显著超过所有人类选手的平均水平**。

**奖励设计**（§2.2）：`Reward_rule = Reward_acc + Reward_format`，两项同权重。
准确性奖励判答案对不对（数学题要求把答案放进指定格式后做规则比对；代码题跑测试用例）；
格式奖励要求把推理过程包在 `&lt;think&gt;` / `&lt;/think&gt;` 标签内。
**论文明确声明不用神经奖励模型**（outcome-based 与 process-based 都不用），
理由是**神经奖励模型在大规模 RL 中容易被 reward hacking**。详见 `con-0006`。

**涌现的行为**：论文报告出现了**反思式推理与对替代解法的系统性探索**；
并记录了所谓 **"aha moment"**——表现为**反思时 "wait" 这个词的使用频率突然上升**，
论文称这标志着推理模式的明显变化。

**一个外部变量值得单独记住**：每题的采样最大长度在 **8.2k step** 处从
**32,768 提到 65,536**，而**性能与响应长度在这一步同时跳变**。总训练 **10,400 step ≈ 1.6 个 epoch**。
→ 长度曲线有拐点时，**先查是不是有人改了长度上限**。

## ⚠️ 它的代价：R1-Zero 没被直接采用（§1、§3）

论文自己列了两条问题：

1. **可读性差 + 语言混杂**——同一条思维链里会混用中英文。
   根因在附录 A.1：基座训练数据以中英为主，**在没有语言一致性奖励时**就会混。
2. **规则奖励只覆盖推理任务**——导致在**写作、开放域问答**这类更广的任务上表现受限。

→ **所以 R1 才需要 cold start。** 而论文说 cold start 的动机**主要是产品驱动的**：
用户更接受**第一人称视角**的思考过程，而且**语言一致性对体验很关键**。
数据是人工标注者把推理轨迹改写成自然对话风格，再用 LLM 扩写、二次人工校验。

**反事实**：如果任务不可验证（比如写作质量），这条路径走不通——
没有程序能给奖励，就必须回到奖励模型或人工。**这正是 `con-0006` 的边界。**
而 R1-Zero 在写作/开放域上的受限表现，就是这条边界的一次实测。

**这条案例与 `stance-0002` 的张力**：R1-Zero 把涌现归给 RL；
Dr. GRPO 提醒其中一部分可能来自基座（它测到 DeepSeek-V3-Base 在 RL 前**已有自我反思**，
且自我反思与更高准确率**无正相关**）。**两条都挂在结构里，本结构不替读者裁决。**
