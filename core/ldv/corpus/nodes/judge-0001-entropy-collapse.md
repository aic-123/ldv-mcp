熵掉本身不说明问题。要看的是这三样一起：

变量：熵下降的速率、同一组内多条采样的重合程度、被裁掉的 token 落在概率分布的哪一侧

**DAPO 给的诊断口径**：策略熵随训练**快速**下降、**同一组的采样响应趋于近乎相同** →
这是熵坍缩，探索受限，会过早进入确定性策略。

**它给的对策是 Clip-Higher**：把裁剪范围解耦成上下界两个参数，**只放大上界**。
理由是上界裁剪会限制**低概率（探索）token** 的概率提升，而高概率（利用）token 更容易被抬高——
所以问题出在上界，不在下界。

## 怎么确认

1. 把 entropy 曲线拉出来，看**下降速率**——DAPO 的措辞是"**快速**下降"，不是"在降"
2. 对同一个 prompt 的 k 条采样**两两比对**，看它们是不是"**趋于近乎相同**"
3. 去实现里看被裁掉的 token 落在**哪一侧**——上界裁剪的多是低概率（探索）token

**第 2 步才是判据，第 1 步只是信号。** 熵低本身说明不了问题——
一个已经很确定的策略本来熵就低。**"组内趋同"才说明这一组失去了分辨力。**

⚠️ **来源强度要说清**：DAPO 给的是**机制解释**（上界裁剪限制低概率 token 的概率提升），
**不是一条现成的日志字段**。第 3 步要自己在实现里加裁剪侧别的统计，
本节点把这条读法写出来，但**不声称论文给了它**。
