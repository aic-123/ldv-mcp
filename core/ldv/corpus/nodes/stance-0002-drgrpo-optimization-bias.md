**主张**：GRPO 的目标函数里有两个归一化项，**每一项都引入一个偏差**。
论文原话：`both std and |o| should not appear in the RL objective`。

## 偏差一：响应级长度偏差（来自 `1/|o_i|`）

对**正优势**（正确回答）：除以 `|o_i|` 使得**短回答得到更大的梯度更新**
→ 策略倾向于**在正确答案上偏好简短**。

对**负优势**（错误回答）：`|o_i|` 大反而**被惩罚得更少**
→ 策略倾向于**在错误回答上偏好更长**。

→ 注意这两个方向是**相反**的。所以「长度增长」这个笼统指标会把它们混在一起。

## 偏差二：问题级难度偏差（来自 `std(R)`）

把中心化奖励除以组内标准差，结果是：
**标准差低的问题——也就是太容易或太难、奖励几乎全是 1 或 0 的那种——在策略更新中被赋予更高的权重**。

→ 这与 `judge-0002` 描述的「一组全对或全错」是同一处，但**结论相反**：
一边说那一组"白跑了"，一边说那一组"被加权了"。**两说都来自一手论文，本结构只列不裁。**

## 修法：把两项都拿掉

论文的做法是**同时移除** `1/|o_i|` 与 `std(R)`，并在实现里把按 mask 求平均换成除以常数
（如生成预算 MAX_TOKENS）。改动后目标恢复成标准 PPO 形式，优势用蒙特卡洛回报加无偏基线。

**一个必须记住的等价性**：修正后的优势估计与 **RLOO** 的优势估计
只差一个常数因子 `G/(G-1)`——**可以并入学习率**。
也就是说，Dr. GRPO 在数学上**不是一个新算法，而是把 GRPO 拉回到 RLOO 那一族**。

## 一个超出 GRPO 范围的补充发现

论文查了开源实现，发现 **trl、OpenRLHF、verl、SimpleRL-Zero、Open-Reasoner-Zero
的 PPO 损失普遍按响应长度归一化**，与标准 PPO 目标不一致——**同一个长度偏差也存在于 PPO 实现里**。
论文推测这个错配源自预训练阶段按上下文长度归一化的习惯。

→ 含义：**这不是"GRPO 的毛病"，是"长度归一化这个动作的毛病"。**

## 基座侧的发现（这条比算法部分更让人不安）

论文把**基座和算法分开检验**，结果指向「涌现的一部分可能属于基座」：

| 观察 | 具体数字 |
|---|---|
| Qwen2.5-Math **不加模板**时表现最好 | 1.5B：4-shot 19.7 → 无模板 **33.1**；7B：4-shot 23.8 → 无模板 **38.2** |
| 加 R1 模板反而崩 | 1.5B 仅 **7.9**；7B **0.0** |
| 不用模板相对 4-shot 的提升 | 约 **60%** |
| 论文的假设 | Qwen2.5-Math 预训练时用过 chat 问答对 → **基座已经是"SFT-like"的** |
| 因此的警告 | 用 Qwen2.5 复现 R1-Zero 要**更谨慎** |
| DeepSeek-V3-Base 在 RL **之前** | 已表现出相当数量的**自我反思**（含 "Aha"、"wait" 这类词） |
| 自我反思与准确率的关系 | **无正相关**——约一半带自省的响应并未取得更高准确率 |
| 弱基座 + 领域继续预训练 | Llama-3.2-3B 原始 Avg 3.3 → RL 后仅 **6.8**；经 FineMath 继续预训练 → **14.8**；经 NuminaQA → **20.7** |

论文自己的克制声明值得照录：

> 我们应当**更保守地**声称"纯 RL 带来了巨大提升"。

**这条与 `case-0003` 构成张力**：R1-Zero 把涌现归给 RL；这篇提醒其中一部分可能来自基座。
**两条都挂在结构里，本结构不替读者裁决。**

## 论文自己给的边界

1. **长度增长的解释是被混淆的**（第 3.2 节脚注）：有人用 PPO（公式上无偏）也观察到长度增长，
   但他们的损失实现仍引入长度偏差——所以观察到的长度增长
   **也被响应级长度偏差混淆了**。
2. **错误回答更长这件事本身也可能有别的解释**：难问题需要更长推理，而错误更可能来自难题。
3. **自省检测方法有误分类**：用关键词 + LLM 交叉验证降低假阳性，但两种方法都会误判。
4. **实验范围有限**：数学推理基准、Qwen2.5-Math 与 Llama-3.2 系列、生成预算 3k。
