**为什么需要这一层**：`judge-0004` 说的是「截断样本的奖励怎么给」——
那是**已经知道问题出在截断**之后才问得出来的问题。
但真实的第一句话是**「reward 崩了」**，这时候你还不知道原因。

所以本节点只做一件事：**把「reward 崩了」拆成四个可分别去查的方向。**

变量：reward 曲线的走向、这批样本的假阴性率、截断样本占 batch 的比例、进训练的组里奖励方差为 0 的比例

## 分诊表

| 你看到的 | 大概是什么 | 去看 |
|---|---|---|
| **奖励是 0，但推理过程看起来是对的** | 判分规则没匹配上——最常见的是答案被截断，`Answer:` 那段根本没生成出来 | `judge-0004` |
| **一批 prompt 的奖励全是 1（或全是 0）** | 这些组组内奖励无方差 → 优势为 0 → 白跑 | `judge-0002` |
| **奖励判分本身依赖格式，而格式又依赖长度** | 奖励函数把「格式对不对」和「答案对不对」绑成了一件事 | `con-0006` |
| **上面三条都排除了，但曲线还是崩** | 问题不在奖励侧，去看熵与训练-推理偏差 | `judge-0001`、`judge-0006` |

不是奖励侧的病因。）

**第一条是最容易被漏掉的一条**：判分规则是**确定性纯函数**，
所以它的失败是**可枚举的 bug**，不是统计现象——
**你把 rollout 捞出来逐条对一遍就能确认，不需要任何统计方法。**

## 怎么确认

把同一批 rollout 的**原始文本**和**它拿到的奖励**并排放：

1. 逐条读推理过程，人工判它**该不该算对**
2. 和它**实际拿到的分**对比
3. 统计**「推理对但给了 0」的比例**——这就是假阴性率
4. 再看这些假阴性样本**有什么共同点**（长度顶到上限？格式少了一行？）

**第 4 步是关键**：如果假阴性的样本**集中在某个长度段**，
那问题就不是「奖励函数写错了」，而是「奖励函数和长度上限打架了」——
这两种病的修法完全不同。

## 一条边界

**本节点不给阈值。** 假阴性率 5% 和 50% 意味着完全不同的紧迫程度，
而那条线取决于你的判分规则有多严、任务有多难、以及你能接受多少噪声——
那是你的判断，不是本结构能替你做的。

→ 同理，**本节点也不给「该改哪条规则」的答案**：
那要等你看完第 4 步的共同点才能定。
