**默认做法有代价**：对截断样本一律施加惩罚，会让**推理过程本身合理、只是太长**的回答也被罚。
那部分惩罚就是奖励噪声。

变量：截断样本占 batch 的比例、截断样本里的过程质量、惩罚是二值还是随长度渐变

**两条来源各给了一半：**
- **教材（偏奖励模型场景）**：截断是 RLHF 的失败模式——奖励模型在训练分布外的长度上打分不可预测。
  对策是**只在 `eos_token` 上跑奖励模型评分**，否则就对过长生成施加惩罚。
- **DAPO（偏规则奖励场景）**：给出两种做法——**Overlong Filtering**（屏蔽截断样本的损失）
  与 **Soft Overlong Punishment**（长度感知的分段惩罚：超过 `L_max − L_cache` 后越长罚越多）。

## 怎么确认

1. 统计**截断样本占 batch 的比例**（按有没有生成出 `eos`、或长度是否顶到上限来判）
2. 把这些样本的**原始文本捞出来**，人工看过程质量——推理本身是不是合理的
3. 去读奖励函数**代码**，看惩罚是**二值**还是**随长度渐变**
4. 如果疑点是「推对了却给了 0 分」，**假阴性率的四步统计在 `judge-0009`**，不在这里重复

**第 3 步为什么必须读代码**：两条来源说的不是同一件事——
教材讲的是**奖励模型**在分布外长度上打分不可预测；
DAPO 讲的是**规则奖励**下「统一惩罚截断样本」会引入噪声。
**你用的是哪一种，只有代码知道。** 用错那一套，对策也是错的。

⚠️ 两条来源都**没有**给「截断比例多少算高」——所以本节点不写那条线。
