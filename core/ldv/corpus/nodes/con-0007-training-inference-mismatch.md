同一份权重、同一条输入，rollout 引擎和训练引擎算出来的 token 概率**可以不一样**。
这不是 bug，是现代推理栈的常态。

**两个来源**：

1. **实现差异**——推理引擎用为吞吐优化的 kernel（如 FlashInfer），训练引擎用不了。
2. **归约顺序与分块差异**——即使同一个 kernel，原子加法等性能优化会引入非确定性；
   **batch size 一变，auto-tuning 会选不同的 launch grid**，改变 GPU 分块与归约顺序。
   而浮点加法**不满足结合律**，顺序一变结果就变。

**为什么它危险**：

- 它**不是**策略真的移动了。原论文把它定义为**基础设施级噪声**，并强调
  **朴素的 PPO 裁剪修不了它**——裁剪管的是策略移动，不是数值不一致。
- 单看每个 token 差异很小；但 `con-0008` 说过，序列级权重是**连乘**的。
  原论文的测量显示：**每批的平均差异小，极端 token 的最大差异可以到 1.0**（即 argmax 翻转）。
- 它会**悄悄改变优化目标**：因为代理目标对优势的正负号反应不同，
  **对称的数值噪声被转化为有偏的、非零均值的梯度畸变**。
  这时 KL 估计量可能还贴着基线不动，**等它涨起来已经晚了**。

→ 所以「看 KL 有没有涨」不足以发现它。判据见 `judge-0006`。
