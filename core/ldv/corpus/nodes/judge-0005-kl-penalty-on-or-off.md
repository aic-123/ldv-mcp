变量：施加位置（损失层还是奖励层）、系数是静态还是动态、任务是否可验证

**教材给的三条口径：**

1. **位置决定信用分配粒度**。损失层（GRPO 规范实现）保留序列级优势、加逐 token 项；
   奖励层（RLOO / 传统策略梯度）在算优势前逐 token 减掉 KL。
2. **静态 vs 动态**。原始 PPO 实现有**动态 KL 控制器**（针对目标 KL 值、按近期测量调整惩罚）；
   **现代 RLHF 大多改用静态 KL 惩罚**。所以"调 β"和"调目标 KL"是两套不同的动作。
3. **一个趋势**：随 RLHF 转向推理与可验证奖励（RLVR），KL 惩罚的普遍性**整体下降**，
   许多推理向改编版**完全关闭**它。

第 3 条是趋势描述，不是建议——本结构不替你做这个决定。

## 怎么确认

**这条不是排查题，是选型题。** 「怎么确认」在这里的意思是：
**先确认你手上是哪种实现，再谈设多少。**

1. 去代码里看 KL 加在**哪一层**：损失层（序列级优势 + 逐 token 项）还是奖励层（算优势前逐 token 减掉）
2. 看系数是**静态常数**，还是**动态控制器**（针对目标 KL、按近期测量调整）
3. 看任务是否**可验证**（RLVR）——这决定教材第 3 条趋势是否适用于你

**第 1 步决定信用分配的粒度，第 2 步决定你该动的是哪个旋钮。**
"调 β" 和 "调目标 KL" 是**两套不同的动作**——先分清手上是哪一套，再谈值。

⚠️ 三条口径都是**教材给的结构性描述**，教材没有给任何推荐值。
本节点同样不给。
