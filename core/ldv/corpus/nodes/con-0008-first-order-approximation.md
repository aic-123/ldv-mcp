真正要最大化的东西是**序列级**的：整条回答拿到多少奖励。但实际算的损失是**token 级**的：每个 token 的比率乘优势，再加起来。

这两者不是一回事。把它们连起来的是一个**一阶近似**。

**近似怎么来的**：设 token 级重要性权重为 `1+δ_t`，序列级权重就是它们的连乘 `∏(1+δ_t)`，
一阶展开后约等于 `1 + Σδ_t`。于是序列级梯度 ≈ token 级梯度。

**它什么时候失效**——原论文把 token 级权重拆成两个因子，这两个因子就是失效的两个来源：

| 因子 | 含义 | 什么时候变大 |
|---|---|---|
| **训练-推理偏差** | 训练引擎与 rollout 引擎对同一序列给出不同概率 | 两个引擎用不同 kernel；同引擎内 batch-invariant kernel 被关掉换吞吐 |
| **策略陈旧度** | 产生数据时的策略 vs 正在更新的策略 | 一批 rollout 切成多个 mini-batch 做多次更新，越靠后越陈旧；异步 RL 中一条回答可能由多个模型版本接力生成 |

→ **两个因子都必须压住，近似才成立。** 只压一个不够——这是 `con-0007` 与 `judge-0006` 的由来。

**注意「连乘」这件事**：δ_t 每个都很小，但序列级权重是**连乘**的——
序列越长，小偏差累积得越多。所以同一个偏差，在长回答上更危险。
